1.1 과제 개요

로컬 LLM 기반의 이중인격 NPC 구현 및 상호작용 제어 시스템 개발

유니티 엔진과 로컬 LLM을 연동하여 정해진 스크립트가 없는 생성형 AI NPC를 구축한다. 또한 플레이어의 '이중인격'이라는 설정을 활용해 AI가 캐릭터의 통제권을 강탈하고, 대화를 통해 다시 통제권을 쟁취하는 혁신적인 비선형 게임 메커니즘을 탐구한다.

 교수님과의 면담 당시 강조된 ‘게임 수학 및 물리 원리의 명확한 이해와 적용’ 사항을 개발 공정에 적극 반영하고 있다.

우선, 기존 이동 시스템에서 발생하던 부자연스러운 움직임을 개선하고자 게임 수학 기반의 로직 최적화를 최우선으로 진행하였다. 벡터 연산과 가속도 물리 법칙을 플레이어 이동 로직에 정교하게 대입하여 조작감의 이질감을 해결하였으며, 이를 통해 한층 매끄러운 기동성을 구현하였다.

나아가 향후 투사체 시스템 개발 시에도 교수님의 지도를 바탕으로 삼각함수를 활용한 궤적 계산을 적용할 예정이다. 이를 통해 연산 효율을 극대화함은 물론, Rigidbody와 Collider의 상호작용에 물리 역학 공식을 엄격히 적용함으로써 오브젝트 간 충돌 피드백의 완성도를 고도화해 나갈 계획이다.

1.3. 과제 진행 과정 및 내용 상세 

1주차: 프로젝트 기획 구체화 및 시스템 아키텍처 설계

-동적 주도권 전이 메커니즘 설계

LLM을 활용하여 플레이어 캐릭터의 이중인격 페르소나를 구축하고, 특정 트리거 발생 시 제어권이 시스템(AI)으로 강제 이양되는 비대칭적 게임 루프를 기획했다.

대화의 품질과 협상 결과에 따라 캐릭터의 제어권이 복구되거나, AI가 임의로 적진에 돌진하는 등의 행동 페널티를 부여하여 심리적 긴장감을 유도하는 메커니즘을 정의했다.

-서사 기반 가변적 보스 시스템 고도화

고정된 스토리라인에서 탈피하여, NPC와의 상호작용 및 호감도 수치에 따라 해당 NPC가 최후의 적 또는 조력자로 분기되는 관계형 시나리오 알고리즘을 설계했다.

AI NPC의 의사결정 프로세스에 플레이어와의 누적 대화 데이터를 반영하여 매 플레이마다 고유한 서사적 경험을 제공하도록 기획했다.

이에 따라 AI NPC는 단순한 챗봇이 아닌, AI의 판단이 게임의 물리적인 수치에 직접적인 영향을 주게 만들어 AI가 게임을 직접 조절하여 플레이어에게 새로운 느낌을 주는 형태의 게임 메커니즘을 기획했다.

2주차 : 게임의 컨셉에 맞는 무료 2D 에셋(캐릭터,환경) 선정 또는 Nano Banana기반 에셋 생성

디자인이 가능한 팀원이 존재하지 않기에 무료 에셋이나 가격이 싼 에셋을 찾아보았고, 가능한 게임의 환경이 일관성 있도록 느껴지는 에셋을 찾아보았다.

‘대마왕의 침공으로 황폐화된 마을’이라는 서사적 배경을 시각적으로 구현하기 위해, 저채도와 어두운 톤 위주의 환경 에셋 가이드라인을 수립하였다. 

글로벌 인디게임 리소스 플랫폼인 Itch.io를 활용하여 게임 컨셉에 부합하는 고품질 맵 타일셋(Tilemap)을 발굴하고 도입했다.

또한 월드에 몰입감을 주기 위해 NPC가 거주하는 집 또한 저채도 에셋을 찾아보고, 선정했다.

게임 내에서 실제로 사용할 맵 타일셋/ 게임 내 사용할 집 에셋

- 캐릭터 에셋 선정

페르소나와 비주얼의 대조적 설계 

게임의 전반적인 디스토피아적/다크한 분위기와 대비되는 친근하고 인간적인 외형의 플레이어블 캐릭터 에셋을 선정했다.

이는 캐릭터가 겪는 삶의 풍파와 이중인격으로 인한 고난을 시각적으로 극대화하며, 유저로 하여금 캐릭터에 대한 연민과 몰입을 동시에 느끼게 하는 서사적 장치로 활용된다.

이중인격을 표현할 때에는 캐릭터 에셋의 눈 색깔을 빨간색으로 바꾸고, 화면에 글리치 효과를 넣어서 플레이어가 이중인격 AI가 나타났다는 걸 느낄 수 있게 만들기로 계획하였다.

  3주차: 타일셋 제작 및 레벨 디자인 구성 요약

 효율적인 맵 제작과 시각적 완성도를 높이기 위해 총 세 가지 종류의 타일셋을 제작했다.

 먼저 지형 연결을 자동으로 처리하는 흙 타일 룰 타일셋 47개를 구성했으며, 그 위에 배치할 풀 타일셋 9개를 추가했다. 여기에 생동감을 더하기 위해 9개의 프레임으로 이루어진 애니메이션 물 타일을 제작하여 흐르는 효과를 구현했다.

 맵의 전체적인 컨셉은 섬 형태로 디자인했다. 육지를 물로 완전히 둘러싸는 방식을 취했는데, 이는 플레이어가 외부로 나가지 못하도록 막는 동시에 '깊은 물 때문에 건너갈 수 없다'는 자연스러운 환경적 근거를 제공했다. 이를 통해 게임의 몰입도를 해치지 않으면서도 플레이 구역을 명확하게 제한하는 효과를 의도했다.

4주차 : 플레이어 캐릭터 컨트롤러 구현

 본 단계에서는 2D RPG의 핵심 요소인 플레이어 캐릭터의 정교한 조작감을 확보하기 위해 캐릭터 컨트롤러 구현을 진행하였다. 특히 Unity 엔진에서 제공하는 다양한 입력 방식과 물리 제어 메커니즘을 심도 있게 분통해 본 프로젝트의 물리 환경에 최적화된 이동 로직을 도출하고 실제 개발 과정에 적용한 경과는 석하여, 프로젝트의 최적화와 확장성에 가장 부합하는 시스템을 구축하고자 하였다.

 단순한 기능 구현을 넘어, 기존의 Input Manager와 최신 Input System의 구조적 차이를 검토하고, Transform 제어와 Rigidbody2D 물리 연산이 캐릭터 이동의 퍼포먼스와 안정성에 미치는 영향을 비교 분석하였다. 이를 다음과 같다.

Input Manager과 Input System 비교

 2D 탑뷰 RPG는 이동, 상호작용, 스킬 사용 등 다양한 입력이 필요하며, 향후 패드 지원이나 키 변경 기능을 고려한다면 Input System 방식이 훨씬 효율적이고 확장성이 높다. 유니티 공식 문서의 Input Manager 항목에서도 Input Manager를 이전 기술(유산)으로 분류하고, 새 프로젝트에는 Input System 사용을 권장하고 있다.

2D 탑뷰 RPG에서 Input System이 유리한 이유

-다양한 상태 관리: RPG에는 '필드 이동', '전투', '인벤토리 창' 등 상태에 따라 입력값이 달라져야 하는데, Input System의 Action Maps를 사용하면 상태별로 입력을 통째로 껐다 켰다(Enable/Disable) 할 수 있어 로직이 훨씬 깔끔해진다.

-이동 입력의 일관성: 탑뷰 이동 시 키보드(WASD)와 조이스틱의 Vector2 값을 별도의 예외 처리 없이 동일한 로직으로 처리할 수 있다.

-이벤트 기반 최적화:Update 함수에서 매 프레임 키가 눌렸는지 검사(Polling)하는 대신, 입력이 발생했을 때만 함수를 호출하는 C# 이벤트 방식을 사용할 수 있어 성능과 코드 가독성 면에서 유리하다.

또한 유니티 공식 매뉴얼에서도 다음과 같이 명시하고 있다.

"Important: Input Manager is a legacy feature and not recommended for new projects. For new projects you should use the Input System Package.”

(중요: Input Manager는 레거시 기능이며 새 프로젝트에는 권장되지 않습니다. 새 프로젝트에는 Input System 패키지를 사용해야 합니다.)

Rigidbody2D기반 VS Transform.Position기반 움직임 비교

 2D 탑뷰 RPG에서는 캐릭터가 벽이나 장애물에 충돌하고 밀어내는 등의 물리적인 상호작용이 필요하기 때문에 Rigidbody2D를 사용하여 물리 기반 이동 코드를 작성하였다. transform.position 코드는 단순히 좌표만 옮기는 방식이며 물리 연산을 무시하기 때문에 벽을 뚫는 현상이 잦은 반면, Rigidbody2D 기반 방식은 물리적인 상호작용이 훨씬 자연스럽고 버그가 적다.

Input System과 Rigidbody2D를 사용한 플레이어 이동 코드

벽 뚫기(Phasing) 방지 : `transform.position`을 사용하면 캐릭터의 좌표를 강제로 설정하기 때문에, 캐릭터가 벽 안으로 겹쳐질 수 있다. 이를 방지하려면 `Raycast` 등을 이용해 충돌 여부를 직접 코드로 검사해야 하는데, 이는 매우 복잡하고 불안정하다. 반면 `Rigidbody2D`는 물리 엔진이 스스로 계산하여 캐릭터가 벽을 뚫지 못하게 막아준다.

부드러운 미끄러짐 : 탑뷰 RPG에서 대각선 방향으로 벽에 비스듬히 걸어갈 때, 물리 기반 방식은 벽을 타고 부드럽게 미끄러지듯 이동한다. 이는 플레이어에게 훨씬 쾌적한 조작감을 제공한다.

유니티 내 Rigidbody2D 공식 문서에서도 물리적인 상호작용에는 Rigidbody2D를 사용하라고 되어있다.

"Note: You can override the Rigidbody 2D by directly modifying the Transform component yourself... However, this will cause issues such as unpredictable movement or GameObjects passing through and into each other."

(참고: Transform 컴포넌트를 직접 수정하여 Rigidbody 2D를 덮어쓸 수 있습니다... 하지만 이는 예측할 수 없는 움직임이나 게임 오브젝트가 서로 통과해버리는 등의 문제를 일으킬 수 있습니다.)

"Moving the Rigidbody 2D provides the best performance and ensures correct collision detection."

(Rigidbody 2D를 움직이는 것이 최상의 성능을 제공하고 정확한 충돌 감지를 보장합니다.)

-비용 효율성: 지속적인 API 호출 비용 발생 문제를 해결하기 위해, 사용자 기기의 자원을 활용하는 로컬 구동 방식을 채택하였다.

방대한 자료 및 커뮤니티 생태계: 글로벌 커뮤니티에 공개된 수많은 양자화 모델과 최적화 라이브러리, 풍부한 구현 사례를 바탕으로 학생 수준에서도 고성능 AI 시스템을 안정적으로 구축할 수 있는 환경을 활용할 수 있다.

-유니티 연동(LLMUnity): Ollama 서버와 유니티 엔진 간의 통신을 위해 LLMUnity 패키지를 도입하였으며, 이를 통해 스크립트 기반의 비동기 채팅 시스템을 완성하였다.

11주차 : AI 학습 (어둠 인격 LLM 파인튜닝)

-학습 목표 캐릭터 내부의 또 다른 인격인 '어둠(Darkness)'이 몸의 제어권을 두고 플레이어와 협상·위협·회유하는 대화를 수행하도록, 로컬에서 구동 가능한 소형 LLM을 파인튜닝하였다. 출력은 게임 로직이 곧바로 파싱할 수 있도록 항상 {"dialogue":"대사","mood_delta":0} JSON 형식을 따르게 하여, 대사 생성과 감정 수치(mood_delta, -20~+20) 판정을 한 번의 추론으로 동시에 수행하도록 설계하였다.

-학습 데이터 생성 (gen_data.py) 규칙 기반 조합형 생성기: 수작업 라벨링 대신 상황(HP·기분 게이지·적 수·제어자)을 무작위로 조합하는 생성기를 구현하여 약 1,000개의 멀티턴 대화 샘플을 자동 생성하였다. 런타임 정합성: 학습 데이터의 system 프롬프트를 게임 런타임(InnerVoiceManager)에서 실제 사용하는 프롬프트와 동일한 형식으로 맞춰, 학습과 추론 간 분포 불일치를 최소화하였다. 카테고리 기반 일관성: 플레이어 발화를 의미에 따라 항복·반항·달램·거래·모욕·협력 등 12개 카테고리로 분류하고, 카테고리마다 (발화 ↔ 어둠 반응 ↔ mood_delta 범위)를 짝지어 대사 톤과 감정 수치의 방향성이 항상 일관되게 라벨링되도록 하였다. 재현성: 전체 대화를 문자열 키로 비교해 중복을 제거하고 시드(seed=42)를 고정하여 재현 가능하게 하였다.

-모델 및 학습 (train.py) QLoRA 경량 학습: 무료 GPU(Colab T4) 환경에서도 8B급 모델을 학습할 수 있도록, 베이스 모델(Meta-Llama-3.1-8B-Instruct)을 4bit로 로드하고 저랭크 LoRA 어댑터만 학습하는 QLoRA 기법을 적용하였다. 주요 설정: LoRA rank/alpha 16, 4 epochs, learning rate 2e-4(cosine), 유효 배치 8, max sequence length 2048, Unsloth + TRL(SFTTrainer) 프레임워크를 사용하였다.

-배포 (GGUF → Ollama → LLMUnity) 오프라인 구동: 학습된 어댑터를 병합한 뒤 GGUF(Q4_K_M) 포맷으로 양자화하여, 외부 API 의존 없이 완전 오프라인 로컬 추론이 가능하도록 하였다. 연동 경로: 변환된 모델을 Modelfile로 Ollama에 등록(ollama create inner-voice)하고, 유니티의 LLMUnity가 이를 로드하여 대화 추론을 수행한다. Modelfile에는 system 프롬프트와 추론 파라미터(temperature 0.85 등)를 고정해 캐릭터 톤의 일관성과 출력 안정성을 확보하였다.

2주차 : AI 통제권 강탈 (제어권 전환 시스템)

-개념 캐릭터는 하나의 몸을 플레이어와 AI 인격(어둠)이 공유한다. 평소에는 플레이어가 조작하지만 특정 조건이 충족되면 AI가 조작권을 강탈하여 스스로 캐릭터를 움직이고 전투하며, 이는 1주차의 LLM 대화 결과(기분 게이지 변화)와 직접 연동되는 핵심 메커니즘이다. 시스템은 책임 분리를 위해 조건 판정(MoodSystem)·상태 중계(ControlManager)·행동 수행(AIController) 세 컴포넌트로 구성하였다.

-강탈/반환 조건 (MoodSystem.cs) 전투 한정 강탈: 기분 게이지(0~100)는 LLM 대화 결과와 게임 상황에 따라 변동하며, 강탈은 무조건 일어나지 않고 '전투 중'일 때로 한정하였다. 강탈은 전투 중 && 기분 ≤ 20, 반환은 전투 종료 || 기분 ≥ 70 조건에서 발생한다. 실시간 전투 감지: CombatWatch 코루틴이 0.5초 간격으로 일정 반경 내 적 레이어의 존재를 검사해 전투 상태를 갱신하고, 전투 진입·이탈 순간마다 조건을 즉시 재평가하여 전투가 끝나면 기분이 낮아도 곧바로 제어권을 플레이어에게 반환하도록 하였다. 이로써 강탈을 '위기의 순간에만 일어나는 긴장된 사건'으로 만들었다.

-상태 중계 (ControlManager.cs) 느슨한 결합: MoodSystem의 강탈/반환 이벤트를 구독해 제어 주체 플래그(IsPlayerControlled)를 갱신하고 동일 이벤트를 다시 발행한다. 이 이벤트 중계 구조 덕분에 플레이어 입력 처리·AI 행동·연출 효과 등 여러 시스템이 서로를 직접 알 필요 없이 제어권 전환에 반응할 수 있도록 하였다.

-AI 자동 행동 (AIController.cs) 유능한 자동 전투: 강탈이 발생하면 가장 가까운 적을 적이 죽거나 도망칠 때까지 연속 추격·공격하며, 거리에 따라 근거리는 일반 공격, 원거리는 대시 공격, 그 외는 걸어서 접근하도록 분기하였다. 중첩 코루틴을 yield return으로 호출해 제어권 회복 시 모든 하위 동작이 한 번에 중단되도록 하여 코루틴 누수를 방지하였다. 제어권 상실의 대가: AI는 강하지만 몸을 사리지 않아, 적 접촉 범위 안에서는 주기적으로 자신에게 피해를 입어 HP가 깎인다. 이를 통해 'AI에게 몸을 맡기면 적은 잘 처치하지만 대신 몸이 상한다'는 위험-보상 트레이드오프를 게임 메커니즘으로 구현하였다.

-연출 (TakeoverEffect.cs) 체감되는 사건: 제어권이 넘어가거나 회복되는 순간을 플레이어가 명확히 인지하도록 적색 화면 플래시, 카메라 흔들림, 프리셋 대사, 효과음을 트리거하여, 단순한 내부 상태 변화가 아니라 체감되는 사건으로 전달하였다.

2. 자체적인 과제 수행 평가 및 이후 과제 진행 계획 

2.1 과제 진행 상황에 대한 자체 평가

과제를 진행하면서 좋았던 점

-명확한 비전 설정 및 일관된 개발 방향 유지

프로젝트 초기 단계에서 세계관과 기획을 구체적으로 확정하여 개발 방향성을 일관되게 유지했다. 이를 통해 외부 에셋 활용 및 AI 리소스 생성 과정에서 발생할 수 있는 시행착오를 줄이고 전반적인 개발 효율을 높였다.

-독창적인 AI 기반 게임 메커니즘 고안

AI NPC를 단순한 챗봇이 아닌, 캐릭터의 제어권과 물리적 수치에 직접 개입하는 비대칭적 게임 루프로 설계하여 창의적 경쟁력을 확보했다. 특히 상호작용 결과에 따라 서사가 분기되는 관계형 시나리오 알고리즘을 통해 독특한 사용자 경험을 기획했다.

과제를 진행하면서 어려웠던 점

- LLM 통합 설계 및 비용·지연 문제 해결 

초기에는 구현이 간편한 외부 API 연동을 고려했으나, 학생 개발자로서 지속적인 비용 부담과 네트워크 지연에 따른 몰입감 저하 우려를 확인했다. 이를 해결하기 위해 로컬 환경에서 구동 가능한 Ollama와 LLMUnity 라이브러리를 도입하여, 비용 발생 없이 독립적으로 작동하며 보안과 안정성을 갖춘 AI 시스템을 구축했다. 

- 이후 과제 진행 시 보완할 점

-모델 최적화 및 LLM다각적 검토

Llama 모델의 추론 속도 문제를 해결하기 위해 튜닝모델 또는 Gemma4와 같은 최신모델을 실험해볼 것이다. 또한 다른 로컬 LLM모델을 사용할 시에 로컬 환경에서 요구되는 GPU 사양을 재점검하여 하드웨어적 제약 사항을 확인한다.

-수학적 모델링을 통한 로직 구체화

이중인격 AI의 통제권 전이와 같은 복잡한 상호작용 메커니즘을 수학적 알고리즘으로 체계화하여 기술적 완성도를 높인다.
