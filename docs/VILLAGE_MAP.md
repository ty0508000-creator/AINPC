# 생성 마을을 Stage1에 연결

`Assets/Scenes/MapGen_Village.unity`의 지형과 소품을 `Assets/Scenes/Main/Stage1.unity`의 `Village_MapGen` 아래에 복사했다. 원본 생성 씬은 변경하지 않는다.

- 건물 61채·나무 356개·장식 136개·수생 소품 271개와 상대 배치를 보존한다.
- 생성 맵의 플레이어 시작 위치를 기존 마을 `default` 위치에 맞춰 이동한다. 플레이어·카메라·UI는 기존 Stage1의 것을 사용한다.
- 현묵·하연·스미스·카구야와 사냥터 네 입구, 남쪽 재의 왕 문, 북쪽 다음 지역 문을 도달 가능한 빈 땅에 배치한다.
- 건물·물의 충돌을 피하는 연결길을 추가한다. 사냥터 복귀점은 입구와 떨어뜨려 자동 왕복을 방지한다.
- 기존 마을 Grid·옛 연결길·마을의 샘플 몬스터 스폰은 비활성화한다. 같은 씬의 네 사냥터 지형·스폰·목표와 보스 조건은 유지한다.
- `VillageSpawnSafety`는 초기 진입·재도전 시 이전 저장 위치가 새 마을 충돌 타일에 겹치는 경우 출발점으로 옮긴다. 위치 복구 자체는 저장 파일을 쓰지 않는다.

## 저작과 검증

### 일반 주민

schwarnhild의 무료 Summer Village 노인 12명·상인 4명으로 일반 주민 16명을 복원했다. 기존 배치와 E 대화는 유지한다.

주민은 광장에서 연결된 길의 3×3 빈 지형 위에 배치하며, 기존 NPC·입구·복귀점과 주민 사이에 최소 5유닛 간격을 둔다. 충돌체 없이 Y 정렬을 적용한다. 방향별 4프레임 대기 모션을 6fps로 재생하며 현재 주민은 이동하지 않는다. Mana Seed 전용 레이어와 SortingGroup은 씬에서 제거했다.

출처·사용 조건은 Assets/Art/Characters/SummerVillage/README.md와 license.txt에 기록했다. 제작자 schwarnhild를 표기한다. 이전 에셋 파일은 보존한다.

`VillageResidentSetup.Prepare()`는 작업 사본을 만들며, 원본에는 주민의 새 블록과 씬 루트만 추가한다. `VillageResidentSetup.RunPlay()`는 별도 VerificationResults 슬롯을 도메인 재로드 후에도 유지하며 대화 열기·닫기를 검사한다.

Summer Village 복원 시 주민 외형 연결만 복원하고 Mana Seed 전용 레이어를 제거했다. 파일 검사에서 16명과 각각의 대기 프레임 4개를 확인했다. 이번 Unity 플레이 재검사는 에디터 응답 지연으로 완료하지 못했다.

`MapGenVillageSetup.Prepare()`는 임시 작업 씬을 만든다. 대형 Stage1 원본에는 기존 오브젝트의 위치·활성 여부·씬 루트 연결과 새 마을 블록만 반영한다. 기존 씬 GUID와 게임 연결을 보존한다. 옮긴 소품의 Y 정렬도 이동량에 맞춘다.

실제 Unity 6000.3.10f1에서 다음 검사가 통과했다. 플레이 검사는 실제 사용자 슬롯과 분리된 `VerificationResults/VillageMap` 저장을 사용하며 Unity 에디터를 종료하지 않는다.

| 검사 | 결과 |
| --- | --- |
| 원본 타일·소품 보존, 도보 연결, 입구·복귀점 | 31개 통과 |
| 실제 NPC 대화·사냥터 네 곳 왕복·위치 복구·재도전·퀘스트 저장 | 18개 통과 |
| 기존 전체 스테이지 연결 | 166개 통과 |
| 기존 저장·사망 복구 | 62개 통과 |

실제 플레이어의 WASD 도보 경험과 시야·성능 평가는 수동 검사표에서 별도로 기록한다. 위 자동 검사로 수동 플레이 완료를 주장하지 않는다.
