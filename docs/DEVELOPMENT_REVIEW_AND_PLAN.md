# 개발 검토와 실행계획

기준: 2026-09-20 · 현재 코드/퀘스트 데이터/씬 설정과 `2학기_개선계획.md` 대조.

## 결론

지금 필요한 것은 섬과 스킬의 개수를 늘리는 일이 아니라 **첫 섬을 시작해서 선택하고, 싸우고, 죽으면 재도전하고, 저장 후 다시 이어갈 수 있는 한 바퀴**다. 목재 UI는 이 경험을 읽기 쉽게 만드는 기반이지 완성의 증거는 아니다.

권장 1차 목표는 **15~20분짜리 첫 섬 데모**다. 이는 제안한 범위이며 현재 측정된 플레이 시간이 아니다. 대화 1종, 의미 있는 선택 1개, 사용 무공 3개, 보스 1개를 연결한다. 나머지 섬은 이야기 개요로만 보존한다.

검토는 세 종류를 구분한다. ‘확인’은 코드/파일에서 확인한 사실, ‘위험’은 그 구조로 가능한 실패로서 아직 재현하지 않은 것, ‘제안’은 구현하지 않은 개선 방향이다. 이번에 게임오버나 대화 구조를 몰래 변경하지 않았다.

## 1. 목재 UI 검증과 남은 시각 작업

### 적용한 것

- 공식 다운로드한 Fantasy Wooden GUI : Free 2.1에서 PNG 6개와 원본 GUID를 가져왔다. 데모 씬/PSD/외부 실행 코드는 가져오지 않았다.
- 성장 창, 종이 카드, 목재 버튼, 제목, 구분선을 연결했다. 늘어나는 패널과 버튼은 9-slice를 사용한다.
- 밝은 종이색·먹색 본문·옥색 선택 상태를 적용했다. 무공 아이콘은 기존 문양을 유지했다.
- 테스트 저장은 실제 플레이 저장과 분리했다. 사용자가 열어 둔 원본 씬 대신 프로젝트 복사본에서 검증했다.

### 검증의 한계

자동 버튼 콜백 호출은 실제 상태와 저장을 확인하지만 마우스 raycast, 포커스, 입력 장치까지 증명하지 않는다. 빈 검증 씬에서 보이는 화면과 Main의 월드 배경 위 가독성도 다를 수 있다. 해상도별 RenderTexture 캡처는 회귀 확인 자료이며 실제 창 크기 변경 테스트를 대체하지 않는다.

최종 사용자 확인은 C/K 전환 → 강화 → 종료/재실행 → 포인트 유지 → 1/2/3 사용 순서다. 1280×720과 1920×1080 실제 Game View에서도 확인한다. 다른 UI의 중복 표시와 대화 중 단축키 충돌은 Main에서 확인해야 한다.

이번 별도 프로젝트 검사: 기능·저장·목재 연결·버튼 콜백 **30개 통과**, Play 모드 전투 **13개 통과**. 캡처에서 발견한 종이 투명 여백/텍스트 겹침과 상세 버튼 비율을 수정하고 다시 렌더링했다. 수동 기록에는 [검사 기록지](MANUAL_PLAYTEST.md)를 사용한다. 사망·LLM·퀘스트 완주는 이 43개 검사에 포함되지 않는다.

### 다음 시각 개선

1. NPC/퀘스트/내면 대화에 같은 간격·글꼴·색 규칙을 적용한다. 성장 UI부터 확인한 뒤 확장한다.
2. 목재 패키지만으로 무협 정체성이 완성되지는 않는다. 추후 비급 표지, 인장, 검집·옥 장식 중 하나를 핵심 모티프로 선택한다.
3. 아이콘은 이름/실루엣을 먼저 확정하고 제작한다. 32~48px에서 검·방패·내공을 구분할 수 있어야 한다.
4. 선택/잠금/부족 상태를 색만으로 구분하지 않는다. 현재의 상태 문구를 유지한다.
5. 재사용 가능한 스타일 정의는 화면 2개에 적용해 본 뒤 추출한다. 지금 거대한 UI 프레임워크를 만드는 것은 우선순위가 낮다.

## 2. 중요한 비판점과 개선 방법

### P0-1. 사망이 게임의 흐름으로 연결되지 않았다

**후속 구현 완료:** Alive/Dead/Respawning, 재도전 UI/R, 체크포인트(미배치 시 씬 시작 위치), HP/MP 완전 회복, 2초 보호, AI/공격 중단을 추가했다. 성장·퀘스트·Mood는 보존한다. 죽은 저장도 재도전 가능하며 레벨업으로 자동 부활하지 않는다. 살아 있는 적과 처치한 보스는 재생성하지 않는다. 아래 확인/위험은 수정 전 기록이다. 씬별 안전 지점 배치와 Main 실플레이는 별도다. [구현 상세](RECOVERY_AND_SAVE.md).

**확인:** `PlayerStats.OnDeath()`는 로그만 출력한다. Load는 HP 0을 허용하고 종료 시 저장한다.

**위험:** 죽은 상태로 저장한 뒤 재실행해도 정상 플레이로 돌아오지 못할 수 있다. 회복/입력 차단이 코드마다 달라지기 쉽다.

**개선:** Alive/Dead/Respawning 상태와 단일 사망 이벤트를 만든다. 마지막 안전 지점으로 이동, HP/MP 회복, 적 초기화 범위, Mood/퀘스트 보존 정책을 한곳에서 결정한다. 실제 저장을 삭제해 해결하지 않는다.

**완료 조건:** 일반 피해/AI 자해로 사망 → UI 표시 → 재도전 → 조작 정상. 사망 중 종료 후 재실행도 복구. 보상 중복 없음.

**네 결정:** 첫 데모는 ‘마지막 안전 지점 복귀, 성장 유지, 경험치 손실 없음’을 추천한다. 페널티 강화는 재미 확인 후다.

### P0-2. 내면 대화가 무한 대기할 수 있다

**확인:** `InnerVoiceManager`에 `llmTimeout` 필드는 있지만 `ChatStreaming`은 직접 Chat을 기다린다. 컴파일러도 미사용 필드 경고를 낸다. 내면 대화는 시간을 정지시킨다. 기존 README의 ‘양쪽 모두 20초 제한’은 사실과 달라 수정했다.

**개선:** 실제 시간 기준 제한 + 사용자가 닫을 수 있는 경로 + 예외 처리 + 세션 종료 시 시간/입력 상태 복원을 함께 구현한다. 닫는 모든 경로가 같은 정리 함수를 사용해야 한다. 기존 timeScale을 보관하고 소유권 없이 무조건 1로 덮지 않는다.

**완료 조건:** 정상/빈 응답/예외/영구 지연/닫기 각각에서 대화 입력과 게임 시간이 복구된다. 실제 모델 없이 지연을 주는 모의 응답으로도 검사한다.

### P0-3. 늦게 끝난 대화가 새 대화를 오염시킬 수 있다

**확인:** NPC 대화의 `Task.WhenAny`는 기다림을 제한하지만 원래 추론을 취소하지 않는다. 응답 수신 여부는 세션별 ID가 아닌 공유 bool 상태를 사용한다.

**위험:** A 대화를 닫고 B를 열었을 때 A의 늦은 응답이 B의 UI·기억·Mood에 반영될 가능성. 실제 재현은 추가해야 한다.

**개선:** 증가하는 sessionId/requestId를 시작 시 캡처한다. 모든 스트림·await 이후·상태 변경 전에 여전히 유효한 요청인지 검사한다. 라이브러리가 지원하는 취소 API는 별도 확인하고, 취소 성공 여부와 무관하게 오래된 응답을 무시한다.

**완료 조건:** A 지연 → 닫기 → B 시작 → A 완료 순서를 강제로 만들어 B 상태가 변하지 않음을 확인한다.

### P0-4. 퀘스트 문구와 실제 완료 조건이 다르다

**확인:** `isle1_demand`는 ‘인격에게 몸을 맡긴 채 재의 왕을 쓰러뜨린다’고 쓰였지만 목표는 Choice `isle1_demand_accepted`다. `QuestSceneSetup`은 해당 Choice를 구역 진입으로 보고한다. 이는 보스 처치/AI 조작 상태 검증이 아니다.

**개선:** 수락과 수행을 분리한다. 명시적인 선택 UI로 수락하고, 보스 사망 이벤트에 bossId와 판정에 필요한 조작권 정보를 실어 목표를 완료한다. ‘마지막 일격’, ‘전투 전체’, ‘일정 시간’ 중 어느 조건인지 먼저 정한다.

**완료 조건:** 구역 진입만으로 미완료. 거절 시 미완료. 수락+정한 전투 조건을 만족해야 완료. 같은 사망 이벤트가 두 번 와도 보상은 한 번.

**네 결정:** 첫 버전은 구현/설명이 간단한 ‘수락 후, AI 조작 중 보스 처치’를 추천한다. 막타를 기다리는 지루함이 생기면 실험 후 조건을 바꾼다.

### P0-5. 퀘스트의 연결과 이벤트 순서에 검증이 없다

**확인:** 보스 완료가 `isle2_arrival`을 해금하지만 해당 데이터는 없다. `QuestGiver`는 퀘스트 시작보다 먼저 ReportTalk를 호출한다.

**위험:** 같은 NPC의 첫 대화가 새 퀘스트 목표에 잡히지 않을 수 있다. 다음 섬 연결이 조용히 끊긴다.

**개선:** 데모 끝은 존재하지 않는 다음 퀘스트 대신 명확한 ‘첫 장 완료’ 화면으로 표현한다. 대화 완료 이벤트의 시점을 수락/선택 흐름과 맞춘다. 편집기 검증으로 중복 ID, 없는 prerequisite/unlock, 잘못된 requiredCount를 찾는다.

**주의:** 생존자 실패 후 균열 해금은 명시적 unlock 경로가 있다. 선행 조건만 보고 실패 루트가 무조건 막힌다고 판단하면 안 된다. 성공/실패 양쪽을 회귀 검사한다.

### P0-6. 개별 저장 성공이 전체 게임의 저장 성공은 아니다

**후속 구현 완료:** 성장·체크포인트·Mood·퀘스트를 `player_save.json` 단일 스냅샷으로 묶었다. 퀘스트 종료 상태를 보상 수령 표식으로 사용해 EXP/Mood와 같은 파일에 기록한다. 중간 레벨업 저장/콜백을 제거하고 핵심 상태 변경 후 저장, 이후 알림/연출 순서로 처리한다. 주 파일 없음/손상 시 백업, 기존 분리 파일 읽기, 미래 형식/복구 불가 파일 덮어쓰기 방지도 추가했다. 아래 내용은 수정 전 기록이다. RAG/연출은 별도 외부 효과이며 exactly-once를 보장하지 않는다. [검증과 제한](RECOVERY_AND_SAVE.md).

**확인:** 플레이어와 퀘스트는 별도 파일이다. 퀘스트 보상 EXP 지급 중 플레이어 저장이 먼저 발생할 수 있다. 퀘스트 저장은 직접 파일 쓰기이며, 플레이어 로드는 주 파일이 없으면 백업을 읽지 않는다.

**위험:** 두 파일 사이에 종료되면 이미 받은 보상을 다시 받거나 진행이 어긋날 수 있다. 이는 이번 검사로 재현한 장애가 아니라 저장 순서에서 도출한 위험이다.

**개선:** 보상에 영속적인 claimId를 둬 재지급을 막고, 공통 revision 또는 단일 스냅샷 저장을 설계한다. 파일 교체·검증·백업 정책을 통일한다. 신규 게임/복구/마이그레이션을 구분한다.

**완료 조건:** 보상 적용 직전/직후 강제 종료, 손상된 파일, 주 파일 없음, 옛 버전 파일 각각에서 ‘보상 최대 한 번’과 복구 결과를 검사한다.

### P1-1. 연구 목표인 ‘기억 → 행동’이 아직 연결되지 않았다

**확인:** `AIController`는 가까운 적과 거리로 행동하고 기억 기반 성향을 읽지 않는다. ForceDash API가 존재하는 것과 실제 AI가 호출하는 것은 다르다.

**개선:** 먼저 보호/공격 두 가지 프리셋만 만든다. 기억 판단 결과를 허용된 enum으로 전달하고 전투 코드는 거리·위험도·HP 제한을 지킨다. LLM이 임의 코드나 보상·피해 수치를 실행하게 하지 않는다. 모의 입력으로 행동 전환을 완성한 뒤 RAG를 연결한다.

**완료 조건:** 같은 전투 초기 조건에서 성향만 바꿔 거리 유지/돌진 등 관찰 가능한 차이가 난다. 그 차이를 로그로 남긴다. 기억 문장만 달라지는 것은 행동 적응 성공이 아니다.

### P1-2. JSON 복구와 모델 품질 평가가 섞여 있다

**확인:** `LLMResponseParser`는 JsonUtility와 정규식 복구를 사용한다. 복구된 응답도 ParseOk가 될 수 있다. 누락 필드는 기본값으로 해석될 여지가 있다.

**개선:** StrictValid / Repaired / Failed를 나눈다. 필수 키·타입·길이를 검사하고 Mood 범위 제한을 유지한다. grammar는 형식 안정화를 돕지만 대사의 사실성·캐릭터 일관성을 보장하지 않는다.

**완료 조건:** 누락 키, escaped quote, 코드펜스, 과도한 수치, 빈 문자열, 잘린 JSON 테스트. 실패 응답은 안전한 대사와 변화량 0으로 처리하고 원문을 플레이 UI에 노출하지 않는다.

### P1-3. 모델 교체의 기대 효과가 측정값처럼 취급된다

**확인:** 현재 Main의 두 대화 서버는 같은 darkness 경로를 참조한다. 예전 문서의 ‘서로 다른 8B 두 개’, RAM 12~14GB, 3B 전환 속도 배수는 현재 실측으로 확인되지 않았다.

**개선:** 목표 PC에서 현 모델의 냉시작/웜시작, 첫 토큰/완료 지연, 프로세스 RAM/VRAM, 대화 성공률을 먼저 측정한다. 같은 질문 집합으로 후보 모델을 비교한 뒤 교체/재학습을 결정한다. 작은 모델이 반드시 한국어 품질과 총 완료 시간을 개선한다고 가정하지 않는다.

**완료 조건:** 기기 사양, 모델 파일 식별 정보, 추론 설정, 표본 수, 실패 수, 중앙값/p95가 남는다. 실패·타임아웃 표본을 빼고 속도만 비교하지 않는다.

### P1-4. 무공 ‘트리’는 지금 세 개의 선형 성장 줄이다

**확인:** 3계열×3노드, 각 노드는 하나의 선행 인덱스를 가진다. 저장도 배열 인덱스에 의존한다.

**개선:** 현재 규모에서는 배열을 유지해도 충분하다. 노드를 크게 늘리기 전 안정적인 skillId와 저장 마이그레이션을 도입한다. 분기 수보다 플레이 방식이 바뀌는 선택 1개를 우선한다. 무료 재분배는 밸런스 테스트 편의를 위해 검토한다.

**완료 조건:** 공격/방어/회복 투자 결과가 같은 보스에서 체감된다. 신규 노드 추가 후 기존 저장이 다른 스킬로 바뀌지 않는다. 스킬 수 증가 자체는 완료 기준이 아니다.

### P1-5. ‘정신의 균형’과 ‘어둠의 만족도’가 혼재한다

**확인:** UI는 정신의 균형을 표시하고, 일부 퀘스트는 내면의 요구를 수락하면 Mood를 높인다. 플레이어가 왜 조작권을 얻거나 잃는지 설명이 필요하다.

**개선:** 하나의 게이지가 무엇인지 기획 문장으로 고정한다. 첫 데모에서는 ‘두 존재의 협력 안정도’처럼 행동과 결과를 설명할 수 있는 정의를 추천한다. 수치가 바뀌면 원인과 다음 임계 상태를 보여준다.

**완료 조건:** 처음 플레이한 사람이 ‘왜 방금 조작권이 바뀌었는지’를 개발자 설명 없이 말할 수 있다.

### P2. 범위와 일정이 기능 나열 중심이다

기존 계획의 경량 모델, grammar, RAG 메타데이터, 통합 기억 계층, 전투 프로필, 오디오, 멀티턴을 모두 병행하면 통합 확인이 늦어진다. 특히 기억→행동이 뒤로 밀리면 중간 발표에서 핵심 주장을 보여줄 수 없다.

**개선:** 아래 게이트 순서를 따른다. 구조 통합은 작동하는 최소 흐름을 확보한 후 수행한다. 첫 섬 완주가 안 되면 두 번째 섬을 시작하지 않는다. 모델 학습과 아트 제작도 필수 경로를 막지 않게 분리한다.

## 3. 이야기 보강 — 전체 설정은 지키고 첫 장은 작게

임상 설명처럼 ‘PTSD라서 새로운 인격이 반드시 생긴다’고 단정하지 말고, 이 작품의 환상적 내면 존재와 트라우마 서사를 구분한다. 내면의 존재를 악의 원인으로만 쓰기보다, 한때 생존에 도움이 됐지만 지금은 다른 선택을 요구하는 존재로 설계하면 협상 시스템과 연결된다.

먼저 과거 사건의 시간 순서를 정한다. 주인공은 마을을 떠나 천마와 싸웠는가? 당시 알 수 있었던 정보는 무엇인가? 정말 돌아갈 수 있었는가? ‘내가 가지 않았더라면’이라는 믿음과 실제 사실을 구분해야 후반 반전이 억지스럽지 않다.

### 첫 섬 권장 퀘스트 배치

1. **깨어난 검객:** 안전 지점에서 이동/기본 공격. 늙고 약해진 몸을 짧은 행동으로 보여준다. 긴 회상 영상은 미룬다.
2. **남겨진 흔적:** 마을 사람 한 명과 대화. 과거의 영웅담과 현재의 파괴를 대비한다. 첫 능력치 투자로 성장 규칙을 배운다.
3. **이번에는 돌아간다:** 구조 요청과 길을 막는 적. 선택 UI로 돕기/보류를 고르고, 선택 사실을 기록한다. 단순 구역 진입을 선택으로 취급하지 않는다.
4. **몸을 빌려라:** 위험한 전투에서 내면이 개입. 같은 적을 다른 성향으로 상대하는 짧은 경험을 준다. 대화 실패도 진행 중단 대신 다른 반응으로 이어진다.
5. **불완전한 기억:** 유품/증언 1개. 주인공의 죄책감이 전부 사실은 아닐 수 있다는 단서만 준다. 곧바로 모든 책임을 없애는 반전은 피한다.
6. **재의 왕:** 기본 공격, 회피, 사용 무공 하나씩을 쓰게 하는 보스. ‘내가 모두 해결해야 한다’는 습관과 협력 선택을 시험한다.
7. **첫 장의 끝:** 보상과 저장, 생존자 반응, 다음 섬 단서. 실제 다음 섬이 없으면 분명한 데모 종료 화면을 보여준다.

나머지 섬의 후보 주제는 부정/분노/신뢰/수용처럼 구분하되, 각각 새로운 전투·선택 구조를 동반해야 한다. 매 섬마다 동료를 잃고 내면이 폭주하는 같은 장면을 반복하지 않는다. 천마전의 성취는 ‘질환의 완치’가 아니라 불안 속에서도 자기 선택을 지속하는 행동으로 표현한다. 이 배치는 제안이며 현재 씬 배치 완료를 뜻하지 않는다.

## 4. 실행 순서와 통과 조건

기간은 2인 개발 기준의 작업 순서 제안이다. 정해진 학사 마감일이나 보장 일정이 아니며, 각 단계가 실패하면 범위를 줄이고 다음 단계로 넘기지 않는다.

### 1단계 — 현재 화면 승인과 기준선 확보

개발: 목재 UI 연결·캡처·회귀 검사. Main에서 폰트·중복 HUD·입력 동작 확인. 현재 저장을 백업하고 테스트 슬롯 분리.

너: 밝기/글자 크기/목재 질감 승인. 목표 PC와 화면 해상도 기록. 게임오버 정책, Mood 의미, 첫 섬 종료 지점을 결정.

통과: C/K/강화/저장/1·2·3을 직접 사용해 보고 막히는 동작이 없음.

### 2단계 — 멈추지 않는 데모 기반 (우선 작업 1~3일 분량)

개발: 사망/복귀, 내면 타임아웃, 세션 격리, 입력·시간 복구를 작은 변경 단위로 구현. 지연/예외 모의 테스트 추가.

너: 죽기, 대화 중 닫기, 빠르게 다른 NPC로 이동하기를 반복해 재현 순서를 기록.

통과: 정상/실패 경로 모두 조작 가능 상태로 돌아옴. 새로운 스킬·섬 추가는 아직 하지 않음.

### 3단계 — 첫 섬의 참된 진행 (다음 작업 2~3일 분량)

개발: 선택/전투 이벤트 연결, 없는 퀘스트 ID 검사, 보상 중복 방지, 종료 화면. 현재 전투 자산으로 최소 보스를 연결하고 고유 패턴은 이후 추가.

너: 대사·선택 결과를 확정하고 실제 진행 순서대로 NPC/목표 위치를 검토. 임시 격자 배치를 최종 배치로 착각하지 않기.

통과: 새 저장으로 첫 장 종료, 재실행 후 이어하기, 성공/실패 분기 각각 완주.

### 4단계 — 기억이 행동을 바꾸는 최소 실험 (다음 작업 2~3일 분량)

개발: 두 전투 성향, 허용된 의도 매핑, 계측. 모의 기억으로 먼저 검증하고 실제 검색과 연결. 현재 모델과 후보 모델 비교는 이 기준선 이후.

너: 같은 상황에서 반응이 달라져야 하는 사례 10개 작성. 기대하는 차이를 대사와 행동으로 따로 적기.

통과: 기억 없음/있음 조건의 행동 차이가 재현되고, 보호 성향이 실제로 자살 돌진하지 않음.

### 5단계 — 낯선 사람에게 플레이시키기 (다음 작업 1~2일 분량)

개발: 실행 빌드, 모델/임베딩 누락 안내, 로그 익명화, 크레딧 점검. UI 전체 통일은 막히는 화면부터.

너: 3~5명에게 말로 길을 알려주지 않고 플레이 요청. 완료 시간, 길을 잃은 곳, 죽은 이유, 조작권 전환 이해 여부를 기록.

통과: 치명적 진행 중단 없음. 테스트 인원은 탐색용이며 통계적 효과를 입증한 연구라고 표현하지 않음.

## 7. 자료구조와 알고리즘에서 주의할 점

현재 9개 스킬은 배열+선행 인덱스로 충분하며 불필요한 그래프 엔진은 필요 없다. 규모가 늘 때는 stable ID → 정의 Dictionary와 별도 저장 DTO로 바꾸고 마이그레이션한다. 순환 선행 조건 검사는 DFS의 방문 중/완료 상태로 O(V+E)에 수행할 수 있다.

퀘스트는 ID Dictionary로 조회하고 이벤트를 받아 목표를 검사한다. 소규모에서는 전체 순회가 단순하고 안전하다. 다수의 퀘스트가 활성화돼 병목이 측정되면 (eventType,targetId) → 활성 목표 목록 인덱스를 추가한다. 상태 변경 중 컬렉션 순회와 연쇄 자동 시작은 이벤트 큐로 분리할지 검토한다.

저장 안정성은 빠른 자료구조보다 순서와 불변식의 문제다. ‘보상은 한 번’, ‘point는 음수가 아님’, ‘저장 revision은 서로 맞음’을 테스트로 보장한다. 대화 동시성도 bool 개수를 늘리기보다 요청 ID와 상태 전이로 해결한다.

자세한 현재 구현 설명은 [RPG_CODE_EXPLAINED.md](RPG_CODE_EXPLAINED.md)를 참고한다. 위 변경안은 설계 제안이며 아직 구현된 것처럼 보고서에 쓰지 않는다.

## 8. 측정과 발표 기준

대화: 냉/웜 지연, 첫 토큰/전체 완료, 타임아웃 포함 실패율, Strict/Repaired/Failed 비율. 성능: 기기별 RAM/VRAM/FPS. 게임: 완주·사망·재시도·길찾기 실패·조작권 이해. 기억: 검색 적합성과 행동 변화 각각 평가.

원문 대화 로그는 개인정보를 포함할 수 있으므로 기본 공개 자료로 쓰지 않는다. 테스트 동의를 받고 식별 정보를 제거한다. 학습과 평가에 같은 템플릿의 거의 같은 문장이 섞이지 않게 한다. 기억 효과 비교 시 모델·맵·스탯을 동시에 바꾸지 않는다.

발표 문구는 ‘구현했다 / 이번 테스트에서 확인했다 / 아직 제안이다’를 구분한다. UI 테스트 통과를 LLM 시스템 전체 안정성이나 다섯 섬 완성으로 확대 해석하지 않는다.
