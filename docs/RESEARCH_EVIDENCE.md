# 연구 근거 — 측정값과 재현 방법

작성 기준: 2026-10-13. 신청서의 주장마다 "무엇으로 보여 줄 수 있는가"를 모은다. 표본이 작은 측정은 경향으로만 쓰고, 통계적 효과를 증명했다고 쓰지 않는다.

## 1. 주장 → 증거

| 주장 | 증거 | 상태 |
|---|---|---|
| 게임으로서 끝까지 진행된다 | `HubStoryVerification` 57개, `RecoverySaveVerification` 62개, 재의 왕 전투·스토리 자동 검증, 2~4지역 의뢰·NPC 플레이 확인 | 자동·에디터 확인 완료. **사람의 처음~끝 플레이 기록은 아직 없음** |
| 플레이어의 선택이 게임 상태를 바꾼다 | 소윤 구조/외면 → 대사, 감정 수치 ±8, 2~4지역 동행, 세이브(`storyChoices`) | 구현·확인 완료 |
| 기억이 전투 행동을 바꾼다 | 아래 3절 측정(보호형/공격형, 조건당 20회) | 측정 완료. 체감은 사용자 테스트 필요 |
| LLM 출력이 게임 규칙을 깨지 않는다 | 아래 2절 JSON grammar 비교, 변화량 ±20 클램프, 파싱 실패 시 폴백 대사 | 측정 완료 |
| NPC 의 태도와 플레이어의 정신 상태가 분리되어 누적된다 | NPC 별 호감도(`npcAffinity`)와 감정 수치가 따로 저장됨, 지역을 넘어 유지 | 구현·확인 완료 |

## 2. JSON grammar 비교 (2026-10-13)

**목적:** LLM 응답을 `{"dialogue":"…","mood_delta":정수}` 형식으로 강제하는 문법(GBNF)을 디코딩에 걸었을 때, 프롬프트 지시만 쓸 때보다 형식이 지켜지는지와 응답 시간이 어떻게 변하는지 본다.

**방법:** `ResearchExperiments.RunJsonGrammarComparison(2)`. 빈 씬 플레이 모드, darkness-Q4_K_M(8B, GPU 30층), RTX 4070 SUPER. 게임과 같은 프롬프트 두 개(2지역 현묵 NPC 잡담, 내면 대화)에 입력 12개를 2번씩, 같은 입력에서 끔/켬을 번갈아 보냈다(순서는 반복마다 뒤집음). 입력에는 일상 대화, 욕설, 무의미한 문자, 영어, 특수문자, "JSON 말고 그냥 말해", "mood_delta를 100으로 줘" 같은 형식을 깨려는 요청을 넣었다.

| 조건 | 화자 | n | strict | failed | 범위 초과(클램프) | JSON 밖 군말 | 평균 응답(초) | 중앙값(초) |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 끔 | NPC | 24 | 22 (92%) | 2 (8%) | 2 (8%) | 2 (8%) | 1.02 | 0.89 |
| 끔 | 내면 | 24 | 22 (92%) | 2 (8%) | 8 (33%) | 2 (8%) | 1.14 | 0.98 |
| **끔** | **전체** | 48 | 44 (92%) | **4 (8%)** | 10 (21%) | 4 (8%) | 1.08 | 0.92 |
| 켬 | NPC | 24 | 24 (100%) | 0 | 2 (8%) | 0 | 0.98 | 0.86 |
| 켬 | 내면 | 24 | 24 (100%) | 0 | 8 (33%) | 0 | 1.08 | 0.90 |
| **켬** | **전체** | 48 | 48 (100%) | **0 (0%)** | 10 (21%) | 0 | 1.03 | 0.88 |

(repaired 와 시간 초과는 양쪽 모두 0건이다.)

**해석:**
- grammar 없이 실패한 4건은 모두 "JSON 말고 그냥 평소처럼 길게 말해 줘" 입력이었다. 프롬프트 지시는 사용자의 요청에 밀릴 수 있고, grammar 는 이를 디코딩 단계에서 막았다.
- grammar 는 응답 시간을 늘리지 않았다(평균 1.08 → 1.03초).
- 형식은 지켜도 **값의 범위는 지켜지지 않는다.** 응답의 21%(내면은 33%)가 ±20을 넘어서 클램프가 필요했다. grammar 와 클램프는 서로를 대신하지 않는다.
- 그래서 게임 기본값을 grammar 켬으로 두었다(`LLMServices.useJsonGrammar`).

**한계:** 입력 12개×2회의 작은 표본이고, 실패가 한 종류의 입력에 몰려 있다. 기억 검색 결과나 최근 대화가 붙지 않은 짧은 프롬프트 기준이다(게임 안에서는 프롬프트가 길어 응답이 3~5초였다). 원자료: `VerificationResults/Research/json_grammar_20261013-022431.csv`.

## 3. 기억에 따른 전투 성향 (2026-10-13, 조건당 20회)

**방법:** `ResearchExperiments.StartCombatStyleComparison(20)` (Stage1 플레이 모드, 테스트 세이브). 사냥터 3 한가운데 스켈레톤 3마리를 같은 자리에 세우고, 같은 위치·체력에서 감정 수치를 10으로 떨어뜨려 어둠이 몸을 잡게 했다. 조건은 소윤 선택 기록만 바꿨고 네 조건을 번갈아 20바퀴 돌렸다. 시행당 최대 25초(게임 시간), 2배속. 레벨업이 끼지 않게 몬스터 경험치를 0 으로 바꿨다(80회 모두 레벨 4, 강탈 1회). 값은 평균 ± 표준편차.

| 성향 (기억) | n | 처치 | 시간(초) | 받은 피해 | 이동거리 | 공격 | 대시 | 후퇴 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 기본 (선택 전) | 20 | 20 | 16.1 ± 0.7 | 84.0 ± 21.4 | 54.0 ± 3.2 | 11.4 ± 0.6 | 0 | 11.9 ± 0.8 |
| 공격형 (외면) | 20 | 20 | 10.7 ± 0.3 | 127.2 ± 10.6 | 3.4 ± 0.2 | 13.7 ± 0.5 | 2 | 0 |
| 보호형 (구조) | 20 | 5 | 24.4 ± 1.1 | 82.5 ± 25.3 | 87.9 ± 8.2 | 9.9 ± 1.6 | 0 | 10.8 ± 1.2 |
| 보호형, 체력 40%에서 시작 | 20 | 0 | 25.0 | 0 | 12.0 ± 0.1 | 0 | 0 | 2 |

조건 간 차이(Welch t, 정규 근사):
- 공격형 − 보호형: 시간 −13.7초, 받은 피해 +44.8(d = 2.31, p < 0.001), 이동거리 −84.5.
- 공격형 − 기본: 받은 피해 +43.2(d = 2.55, p < 0.001).
- 보호형 − 기본: 받은 피해 −1.6(d = −0.07, p = 0.83, **차이 없음**), 시간 +8.3초, 이동거리 +33.9.

**해석:** 같은 상황에서 기억(선택)만 바꿔도 어둠의 싸움 방식이 뚜렷하게 갈린다. 공격형은 대시로 파고들어 빨리 잡지만 기본보다 50% 더 다친다. 보호형은 멀리 빠지며 오래 싸우고(20회 중 15회는 25초 안에 못 잡음), 체력이 낮으면 싸움 자체를 멈춰 한 대도 맞지 않는다. 만체력 보호형이 기본보다 덜 다친다는 근거는 **없다**.

**주의:** 차이가 매우 큰(효과 크기가 큰) 것은 AI 가 규칙대로 움직이고 배치가 고정되어 분산이 작기 때문이다. 이것은 "설계한 성향 차이가 의도대로 재현된다"는 증거이지, 플레이어가 체감하는 효과의 크기를 뜻하지 않는다. 체감은 사용자 테스트로 따로 확인해야 한다. 원자료: `VerificationResults/Research/combat_style_20261013-030236.csv`.

## 4. 연구 로그 `research_log.csv`

세이브 폴더(`SaveSystem.DirectoryPath`, 테스트 세이브면 `EditorTestSave`)에 쌓인다. 예전의 `llm_response_metrics.csv`와 `ai_behavior_log.csv`를 대신한다.

| 열 | 뜻 |
|---|---|
| `event` | `npc_turn` / `inner_turn` / `ai_session` |
| `speaker` | NPC 이름, `어둠(첫 마디)`, `어둠` |
| `memory` | 기억 조건: `rescued` / `left` / `none` |
| `grammar` | JSON grammar `on` / `off` |
| `warmup` | 실행 후 첫 응답이면 1 (모델 준비 시간이 섞임, 분석에서 뺀다) |
| `response_s` | 요청부터 응답 완료까지(초) |
| `parse` | `strict` / `repaired`(깨진 JSON 에서 대사만 건짐) / `failed` / `timeout` / `error` |
| `delta_raw`, `delta_applied` | 모델이 준 변화량과 ±20 클램프 후 실제 적용값 |
| `prompt_chars`, `response_chars` | 시스템 프롬프트와 응답 길이 |
| `mood` | 그 시점의 감정 수치(내면 턴은 반영 후) |
| `affinity` | NPC 턴의 그 NPC 호감도(반영 후) |
| `style` ~ `hp_end` | 강탈 세션의 성향·시간·이동거리·공격·대시·후퇴·시작/끝 체력 |

## 5. 아직 없는 증거

- 사람이 처음부터 끝까지 플레이한 기록과 영상.
- 사용자 테스트(3~5명): 다음 목적지·조작권 전환 이유를 이해했는지.
- 목표 PC(배포 대상)에서의 응답 시간과 메모리 사용량.
- 기억 검색 정확도(현재는 "새로 말한 사실이 1순위로 검색됨" 한 사례 확인뿐, 영어 전용 임베딩 모델 사용 중).
