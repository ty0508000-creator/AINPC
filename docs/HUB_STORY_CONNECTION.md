# 마을 · 사냥터 · NPC · 퀘스트 연결

## 플레이 흐름

Stage1의 마을 지형은 `MapGen_Village`에서 가져온 건물 61채와 기존 강·나무·길을 사용한다. 마을 중심의 NPC, 네 사냥터 입구, 재의 왕 문과 다음 지역 문을 새 지형에 맞춰 재배치했다. [마을 적용과 검증](VILLAGE_MAP.md)을 참고한다.

Stage1(옛 Main)은 마을과 네 갈림길이 있는 중심 씬이다. 사냥터는 같은 씬의 `Zone_Hunt1`~`4`(예전에는 별도 씬 `HuntingGround1`~`4`)이고 마을 문으로 순간이동한다. 야영지 보고 후 남쪽 문으로 `AshKingArena`에 진입한다. 동굴 튜토리얼은 공동 작업자의 담당이다.

마을에서 **촌장 현묵**에게 가까이 가서 **E**를 누른다. 대화를 확인한 뒤 다시 말을 걸어 첫 의뢰를 수락한다. 대화 창은 E 또는 확인 버튼으로 진행하고 ESC로 취소한다. 가까이 가기만 하거나 창을 닫으면 대화 목표가 완료되지 않는다.

| 순서 | 지역 / 입구 | 의뢰 NPC | 목표 | 경험치 |
| --- | --- | --- | --- | --- |
| 도입 | Main 마을 | 현묵 | 도착 → 화재를 부정하는 촌장의 증언 확인 | 0 |
| 1 | 북서쪽 · 잿빛 숲 | 현묵 | 도착 → 요물 3마리 → 현묵에게 보고 | 80 |
| 2 | 북동쪽 · 흔적의 강가 | 하연 | 도착 → 서로 다른 기억 파편 3개 조사(E) → 하연에게 보고 | 150 |
| 3 | 남서쪽 · 무너진 피난처 | 하연 | 도착 → 요물 3마리 → 소윤과 대화해 구조 → 하연에게 보고 | 140 |
| 4 | 남동쪽 · 불씨의 야영지 | 현묵 | 도착 → 적 5마리 → 북쪽 야영지 문양 확인 → 현묵에게 보고 | 180 |
| 보스 | 남쪽 · 재의 왕 전투터 | 자동 시작 | 전투터 진입 → 재의 왕 처치 | 220 + 처치 120 |
| 결말 | Main 마을 | 현묵 | 최종 보고 확인 | 80 |

각 의뢰는 앞 의뢰를 완료해야 수락할 수 있다. 사냥터 입구는 촌장의 첫 증언을 확인하면 열린다. 이후 자유롭게 드나들 수 있지만 해당 의뢰를 수락하기 전 행동은 목표에 누적되지 않는다. 네 사냥터의 남쪽 입구는 각각 Main의 대응 갈림길로 돌아온다.

야영지 보고에서 재의 왕의 흔적을 확인하고 보스 의뢰가 시작된다. 실제 보스 처치 후 현묵에게 최종 보고해야 첫 장 완료를 기록한다. 이 보고에서 재의 왕이 사천왕 중 하나이며 마을을 태우라 명한 자가 최종보스 천마임이 드러나고, 북쪽 문으로 2지역에 간다. 전투와 재도전은 [보스 구현 문서](ASH_KING_BOSS.md)를 따른다.

## 씬과 데이터

- `Assets/Game/Data/HubStory`: 도입 2개·사냥터 의뢰 4개·보스와 결말 2개의 QuestData, 지역별 적과 보스 데이터.
- 각 씬의 `HubQuestSystem`: 동일한 8개 의뢰 목록과 StoryChoiceManager를 연결한다. 기존 Resources의 9개 기획 퀘스트를 이 동선에 자동 시작시키지 않는다. 기존 데이터와 저장 기록은 보존한다.
- Main의 `HubStory`: NPC, 마을 도착 영역, 네 입구, 돌아오는 위치, 기존 지형 위 연결길.
- `HubStoryActor`: 수락·보고·파편 조사·구조를 명시적 확인으로 진행한다. LLM 없이 진행할 수 있는 대사이며 게임 규칙은 QuestManager가 판단한다.
- `StoryConversationUI`: 씬에 저장한 대화 UI. 열리는 동안 시간을 멈추고 닫거나 비활성화되면 이전 시간 배율을 복구한다.
- 적 이름 대신 저장용 식별자 `hub_enemy_1`~`4`로 처치 목표를 구분한다. 다른 지역의 처치로 의뢰가 완료되지 않는다.
- 파편은 각기 다른 수집 ID를 사용한다. 이미 조사한 파편은 재방문해도 중복 획득하지 않는다.
- 구조 선택 `hub_child_rescued`는 통합 저장에 남는다. 구조 선택의 Mood 보너스는 8이다.
- 소윤 앞에서는 "주민을 구한다"와 "두고 떠난다" 중 하나를 고른다. 외면은 `hub_child_left`(Mood −8)로 남고, 의뢰의 Choice 목표는 두 선택 모두 `hub_child_rescued`로 채운다(`StoryChoiceOption.objectiveId`).
- 외면하면 하연의 보고·대기 대사, 촌장의 야영지 이후·결말 대사가 바뀐다(`HubStoryActor.CompleteLine`). 선택 문장은 내면 기억(`inner`)에도 남는다.
- 2~4지역처럼 `StoryChoiceManager`가 없는 씬에서 저장해도 이전 선택을 유지한다. 그런 씬에서는 `StoryChoiceManager.Remembers`가 저장 파일을 읽는다.

## 2~4지역의 마을 사람들

현묵·하연·스미스는 2~4지역 마을에도 따라온다. 소윤은 구했을 때만 따라온다(`HubStoryActor.hideUnlessChoice`). 배치와 의뢰 데이터는 `Tools > AINPC > Stages > 지역 NPC 배치`(`RegionNpcSetup`)가 만들며, 다시 실행하면 각 씬의 `RegionStory`를 새로 만든다. 대사·의뢰 문구의 원본도 이 스크립트에 있다.

- 지역마다 선택 의뢰 2개: 현묵은 사냥터 몬스터 5마리 처치(`r{N}_elder`), 하연은 사냥터의 기억 파편 3개 조사(`r{N}_hayeon`). 데이터는 `Assets/Game/Data/RegionStory/`. 보스 문을 막지 않으므로 안 해도 진행된다.
- E로 말을 걸면 처리할 의뢰(수락·보고)가 있을 때는 버튼 대화, 없을 때는 LLM 잡담이 열린다. 지역 대기 대사가 잡담의 첫 마디이고, 인물 설정에 지역 테마(2 부정, 3 분노, 4 신뢰)와 소윤 선택이 들어간다.
- 1지역의 현묵·하연·소윤에도 같은 잡담을 붙였다. NPC 이름이 같으면 호감도가 지역을 넘어 이어진다.

## LLM 서버와 플레이어 공통 구성

- 대화·내면 LLM과 임베딩 서버는 `Resources/LLMServices` 프리팹으로, 게임 시작 때 한 번 뜨고 씬이 바뀌어도 유지된다(`LLMServices`). 예전에는 1지역 씬에만 있어서 다른 씬에서는 LLM이 없었다.
- 실행 빌드(2026-10-13, Windows 64비트, Mono)에서 두 서버가 CUDA 라이브러리로 뜨는 것을 로그로 확인했다. `LLMServices`가 서버를 띄우기 전에 네이티브 라이브러리 폴더를 직접 정한다. LLMUnity도 같은 시작 단계에서 정하는데 순서가 보장되지 않아, 빌드에서 "llamalib_win-x64_runtime.dll not found"로 실패했었다. 빌드에는 `StreamingAssets/Models`의 모델 4개(약 9.5GB)가 모두 들어간다.
- 내면 대화와 NPC 대화는 같은 LLMAgent를 쓴다. 그래서 NPC 대화창·의뢰 대화·선택지가 열려 있거나 NPC 응답을 기다리는 동안에는 내면이 열리지 않는다(`InnerVoiceManager.CanOpen`). 스토리가 강제로 여는 내면(`ForceOpen`)은 버리지 않고 대화가 끝난 뒤 연다. 반대로 내면이 열려 있으면 NPC 대화가 열리지 않는다.
- 내면 대화는 응답 글자가 `llmTimeout`(기본 20초) 동안 하나도 오지 않으면 요청을 취소하고 "[ 침묵이 흐른다 ]"로 닫는다. 전체 시간이 아니라 진행 없음 기준이라 느린 CPU에서도 글자가 나오는 동안은 기다린다. NPC 대화는 전체 20초 제한이며, 넘기면 요청을 취소한다.
- 감정 수치·조작권·AI 전투·내면 대화·강탈 연출·기억(`MoodSystem`, `ControlManager`, `AIController`, `InnerVoiceManager`, `TakeoverEffect`, `MemoryManager`)은 이제 `Player.prefab`에 있다. 예전에는 1지역(과 일부는 재의 왕 전투장)에만 있어 다른 씬에서는 강탈이 없고, 저장하면 감정 수치가 초기화됐다. 구운 UI가 없는 씬에서는 내면·강탈 UI를 실행 중에 만든다.

## 감정 수치와 NPC 호감도

- **감정 수치**(`MoodSystem.Mood`, 0~100, 정신의 균형): 주인공이 복수에 잠식되지 않은 정도. 내면 대화, 소윤 선택(±8), 보스 처치로 바뀐다. 전투 중 20 이하면 어둠이 몸을 빼앗고 70 이상이면 돌려준다.
- 보스를 쓰러뜨릴 때마다(재의 왕, 2~4지역 보스, 최종보스) 감정 수치가 `MoodSystem.revengeMoodDrop`(기본 10)만큼 떨어진다. 처치 저장보다 먼저 적용해 같은 스냅샷에 남는다.
- **NPC 호감도**(`NPCInteraction.Affinity`, 0~100, 시작 50): NPC 대화의 `mood_delta`는 이제 그 NPC의 호감도만 바꾸고 감정 수치는 건드리지 않는다. 현재 호감도는 대화 프롬프트에 들어가 말투에 반영된다. 통합 저장의 `npcAffinity`에 NPC 이름별로 남고, NPC가 없는 씬에서 저장해도 유지된다.

## 기억에 따른 내면의 전투 성향

조작권을 빼앗길 때 `AIController`가 소윤 선택으로 성향을 고른다. 선택 전은 기본(치고 빠지기), 구조는 보호형, 외면은 공격형이다.

- 보호형: 빠지는 거리 1.6배. 체력 50% 이하면 공격을 멈추고 감지 범위 끝까지 물러난다.
- 공격형: 멀면 대시로 파고들고, 빠지지 않고 붙어서 계속 벤다.
- 강탈이 끝날 때마다 연구 로그(`research_log.csv`, 세이브 폴더)에 성향·시간·이동거리·공격·대시·후퇴·시작/끝 체력을 한 줄씩 남긴다(`event=ai_session`). 형식은 [연구 근거](RESEARCH_EVIDENCE.md).

측정은 [연구 근거 3절](RESEARCH_EVIDENCE.md)(조건당 20회, `ResearchExperiments.StartCombatStyleComparison`). 요약: 공격형은 빠르지만 기본보다 50% 더 다치고, 보호형은 오래 싸우며 체력이 낮으면 싸움을 멈춘다. 만체력 보호형의 피해는 기본과 차이가 없다. 빠지는 거리를 1.0배로 둔 보호형은 기본과 거의 같아서(이동 47~52, 2026-10-12 예비 측정) 1.6배를 채택했다.

## 게임 클리어

최종보스(`final.boss_cleared`)를 쓰러뜨리면 `GameClearScreen`이 "게임 클리어"와 "타이틀로" 버튼을 띄운다.

## 이동과 저장

사냥터의 ScenePortal은 첫 증언 완료 여부를 검사하고, 보스 문은 야영지 의뢰 완료 여부를 검사한다. GameFlow는 이동 전 현재 플레이어와 퀘스트를 통합 저장한다. 저장에 실패하면 이동을 중단한다. 목적지 씬의 대응 SpawnPoint로 배치하고, 사냥터 입구를 재도전 체크포인트로 설정한다. 입구와 출구 영역을 떨어뜨려 도착 직후 자동 왕복하는 현상을 막는다.

기존 Main의 지형·프리팹·LLM 설정을 보존하고 새 연결 오브젝트를 추가한다. 사냥터의 지형은 프로젝트에 이미 있는 MapGen과 타일·소품으로 생성한다.

## 검증

`HubStoryVerification.Run`: 씬 참조, 포탈 목적지, 의뢰 순서, 취소 시 미진행, 조기 보고 방지, 지역 처치 구분, 파편 중복 방지, 구조 선택과 통합 저장을 검사한다.

`HubStoryPlayVerification.Run`: 별도 저장 슬롯으로 실제 Main에서 네 사냥터를 왕복하며 물리 포탈, 도착 위치, 체크포인트, 부분 퀘스트의 유지 여부를 검사한다.

결과는 `VerificationResults/HubStory`에 기록한다. 기존 저장 회귀 검사는 `RecoverySaveVerification.Run`을 사용한다. 사람이 직접 확인할 항목은 `MANUAL_PLAYTEST.md`의 새 동선 검사표를 따른다.

### 이번 검증 결과

- Unity 6000.3.10f1의 분리된 검증 프로젝트에서 씬·의뢰 검사 **66개**, 실제 플레이 왕복·처치·체크포인트·부분 진행 유지 검사 **34개** 통과.
- 기존 저장·사망 복구 **48개**, UI·성장 **54개** 통과. 실제 사용자 저장 슬롯은 사용하지 않았다.
- Main의 기존 직렬화 블록 1,228개를 보존하고 새 블록 140개를 추가했다. 기존 필드는 UIRoot의 자식 연결, 씬 루트 목록, 중복 EventSystem의 활성화 여부만 수정했다.
- 검증용 프로젝트는 기존 에디터 보조 패키지의 컴파일 문제를 피하도록 패키지를 분리했다. 원본 프로젝트 전체 패키지 구성의 빌드 성공을 주장하지 않는다.
- 모델을 복사하지 않은 환경에서 Main의 기존 LLM/임베딩 초기화 오류가 기록됐다. 새 NPC 의뢰와 네 지역 왕복은 그 상태에서도 통과했다. LLM 응답 품질이나 사람의 전체 전투 플레이는 이번 자동 검증에 포함하지 않았다.
- 하연·소윤의 외형은 기존 NPC 스프라이트를 재사용한다. 소윤 전용 캐릭터 아트는 아직 추가하지 않았다.

## 지역별 전투
사냥터 전용 몬스터와 지형 차이는 [HUNTING_REGIONS.md](HUNTING_REGIONS.md)를 따른다. 기존 퀘스트 ID와 조사·구출 좌표는 유지한다.
