- 같은 평가 세트(163문항)를 세 방식으로 3회씩 돌렸다. 감정이 안정 쪽으로 움직이는지 불안 쪽으로 움직이는지(균형 방향)를 맞힌 비율은

- 결론으로 굳히기 전에 확인할 것이 많다. 라벨 검수, 정답이 규칙 표에서 나온다는 점, 문항 수, 모델 학습이 1회뿐이라는 점이다(6절).

## 1. 연구 질문

LLM 이 플레이어의 말에서 NPC(어둠)의 감정 변화를 정할 때, 모델에게 무엇을 출력하게 하는 것이 판단이 정확한가? 세 방식을 같은 조건에서 비교한다.

| 방식 | 모델이 내는 것 | 감정 변화를 정하는 쪽 | 코드의 이름 |
|---|---|---|---|
| 기준선 | 대사 + `mood_delta` (호감도 한 축, 정수) | 모델 | Legacy |
| 직접 형식 (A) | 분노·두려움·신뢰·냉정의 변화량 4개 + 대사 | 모델 | Direct |
| 의도 형식 (C) | 의도 10종 중 하나 + 강도 1~3 + 대사 | 규칙 표 | Intent |

설계 문서 1절의 가설은 "LLM 이 의미를 판단하고 규칙이 감정을 정하는 방식이 수치를 직접 내는 방식보다 판단 정확도·감정 안정성·대사-감정 일치도에서 낫다"이다.
이 보고서는 그중 **판단 정확도**만 다룬다. 나머지 둘은 측정하지 못했다(6절).

## 2. 배경

### 2.1 어둠과 감정 모델

어둠은 천마에게 동료를 모두 잃은 과거의 자신이다(설계 3절). 감정은 여섯 가지(분노·복수심·슬픔·두려움·신뢰·냉정, 0~100)이고,
LLM 이 움직일 수 있는 것은 분노·두려움·신뢰·냉정 네 가지다. 복수심과 슬픔은 이야기 사건으로만 바뀐다.
압박(= max(분노, 두려움) + 0.2 × 슬픔)이 70 이상이 된 전투에서 신뢰가 50 이상이면 몸을 달라고 "요청"하고, 50 미만이면 강제로 빼앗는다.
감정 변화의 방향을 잘못 판단하면 이 분기가 달라지므로, 판단 오류가 게임 안에서 눈에 띄는 결과로 이어진다.

### 2.2 의도 10종과 규칙 표

의도 형식에서 모델은 의도와 강도만 고르고, 감정 변화는 `EmotionRules.IntentBase` 의 표가 정한다.
변화량 = 표 값 × 강도(1~3) × 상황 보정이다. 상황 보정은 체력 30% 이하의 `despair` 가 두려움 ×1.5, 하연을 호위하는 중의 `promise` 가 신뢰 ×1.5 이다.
대화 한 번의 누적 변화는 감정마다 ±20 으로 제한한다. 표는 평가 이론(appraisal theory, OCC)에 따라 설계 문서 5.4 에서 정했고, 표 자체의 타당성은 이번에 검증하지 않았다.

| 의도 | 뜻 | 분노 | 두려움 | 신뢰 | 냉정 |
|---|---|---:|---:|---:|---:|
| entrust | 맡김 | | −3 | +4 | |
| soothe | 달램 | −4 | | +2 | +3 |
| reason | 설득 | −2 | | | +4 |
| promise | 약속 | | | +5 | |
| defy | 거부 | +3 | | −4 | |
| insult | 모욕 | +6 | | −3 | |
| despair | 나약함 | | +4 | −2 | −2 |
| vengeance | 복수 선동 | +4 | | | −3 |
| ask | 과거 질문 | | | | +1 |
| neutral | 그 외 | | | | |

### 2.3 세 방식의 장단점 (설계 5.1)

- 직접 형식은 여러 감정이 함께 움직이는 반응을 그대로 표현하지만, 4B 모델이 숫자 4개를 내야 해서 노이즈가 크다.
- 의도 형식은 분류 문제라 정확도·F1·혼동 행렬 같은 표준 지표로 잴 수 있고, 재학습 없이 표의 수치를 조정할 수 있다. 대신 표에 없는 미묘한 말은 뭉개진다.
- 기준선은 한 축만 움직인다. 왜 몸을 빼앗았는지(화, 두려움, 불신)를 구분할 수 없다.

### 3.3 정답과 지표

정답은 Claude 가 단 의도·강도 초안에 규칙 표(`EmotionRules.ForIntent`)를 적용해 얻은 감정 변화다. 세 조건 모두 이 정답과 비교한다.

- **균형 방향 일치** (세 조건 공통). 균형 = 신뢰 + 냉정 − 분노 − 두려움. 부호(+, 0, −. ±2.5 안은 0)가 정답과 같은 문항의 비율이다.
  기준선은 감정 4개를 내지 않으므로 `mood_delta` 의 부호(±5 안은 0)를 정답의 균형 부호와 비교한다.
- **감정별 방향 일치와 평균 절대 오차** (Intent, Direct). 분노·두려움·신뢰·냉정 각각이고, 방향은 ±0.5 안을 0 으로 본다.
- **의도 정확도, macro-F1, 혼동 행렬, 강도 일치** (Intent). 강도는 정확히 맞은 비율과 ±1 이내 비율을 센다.
- **강도 제거 실험** (Intent). 예측한 의도는 두고 강도만 2 로 고정해 규칙 표를 적용하고, 정답과의 평균 절대 오차를 비교한다.
  감정별 방향은 의도가 정하므로 강도를 바꿔도 변하지 않는다. 그래서 크기의 오차로 본다.
- **형식·대사**. 파싱 성공, 서로 다른 대사 수, 학습 대사 복제(출력 대사가 학습 파일의 어떤 대사와 문자열이 완전히 같은 비율), 응답 시간.

온도 0.6, JSON 문법, 컨텍스트 4096, GPU 층 99, 문항마다 프롬프트를 새로 만든다. 조건마다 3회 반복했다.

  이 7건은 3개 문항에서 나왔다. 그중 2개(`v2_093`, `v2_152`)는 반어 태그가 붙은 문장이고, 나머지 하나는 "네가 있어서 내가 이 모양이야."(`v2_087`, 3회 모두)다.
- **그 외→나약함(6건)** 은 2개 문항("아 졸려.", "오늘 진짜 죽는 줄 알았네 ㅋㅋ")이 3회씩 만든 것이다. 중립 발화가 두려움 +4·신뢰 −2·냉정 −2 로 바뀐다.
- **이웃 의도로의 혼동은 방향을 해치지 않는 경우가 있다.** 의도가 틀린 60건 중 17건은 균형 방향이 그래도 맞았다(예: 맡김→약속은 둘 다 신뢰를 올린다).
  나머지 43건은 방향도 틀렸다. 의도가 맞는데 균형 방향이 틀린 경우는 3건이다(균형 방향 오류 46건 − 43건).
- **혼동 행렬의 큰 칸은 문항 몇 개가 만든다.** 의도 오류는 18문항이 3회 모두, 1문항이 2회, 4문항이 1회 발생했다. 3회 모두 틀린 18문항 중 16문항은 3회 모두 같은 의도로 틀렸다.
  따라서 표의 한 칸이 모델의 일반적 성향인지 특정 문장의 문제인지는 이 세트로 구분하기 어렵다.
- 재현율이 낮은 의도는 모욕(76.2%), 그 외(76.9%), 약속(80.0%)이고, 설득은 100.0% 다.

## 5. 논의

**의도 형식이 이 평가에서 가장 높다.** 균형 방향 90.6% 는 직접 형식(84.3%)과 기준선(66.3%)을 모두 넘고, 감정별 방향·오차도 모두 앞선다.
다만 정답이 같은 규칙 표에서 나오기 때문에 이 결과는 "표를 거쳐 얻는 값에 얼마나 가까운가"를 잰 것이다. 직접 형식은 표가 만든 숫자를 모델이 스스로 재현해야 하지만,
의도 형식은 표를 시스템 쪽에 두고 모델에게는 분류만 맡긴다. 어둠의 감정이 실제로 표대로 움직이는 것이 맞는지는 별개의 질문이고, 이번 평가는 답하지 않는다.

**기준선은 구조적으로 불리했다.** 한 축만 내므로 비교할 수 있는 지표가 균형 방향 하나뿐이고, 그것마저 두 의도가 섞인 문장에서 47.6% 로 낮았다.
다만 기준선의 임계값(±5)과 프롬프트가 다른 조건과 다르므로 격차의 일부는 비교 방식에서 나왔을 수 있다(6절).

**의도 형식의 비용은 표에 없는 말에서 나타난다.** 반어와 혼합 문장에서 의도 정확도가 70% 대로 내려갔고, 가장 비싼 오류(모욕→달램)에는 반어 문장이 들어 있다.
설계는 이런 오류의 피해를 제한한다. 몸 강탈 같은 큰 판정은 코드 이벤트가 정하고 대화는 감정을 가속·감속할 뿐이며, 대화 한 번의 누적은 ±20 으로 막혀 있다(설계 5.7).
이 제한이 실제로 충분한지는 이번에 평가하지 않았다.

**복제는 정확도와 맞바꾼 것이 아니었다.** 같은 학습 문장으로 비교하면 Intent(30.3%)가 Direct(18.4%)보다 학습 대사를 많이 그대로 냈다.
보강 재학습으로 Direct 수준(17.4%)까지 내려갔고 의도 정확도는 변하지 않았다. 대신 약속으로 새는 오류가 늘었다.

응답 시간은 Intent 가 Direct 보다 짧지만(0.40~0.41초 대 0.52~0.61초) 실행 경로가 섞여 있어 참고만 한다.

## 6. 한계

1. **라벨이 검수 전이다.** 163문항 모두 `reviewed: false` 이고 초안은 Claude 가 달았다. 의도 정확도는 "사람이 단 정답"이 아니라 "초안 라벨"과의 일치율이다.
   라벨이 바뀌면 정답 감정이 전부 바뀐다.
2. **문항이 적고 하위 집단은 더 적다.** 의도별 13~21문항(모욕 14, 그 외 13), 태그별 1~14문항이다. 혼동 행렬의 큰 칸도 문항 2~3개가 만들었다.
   상황 보정이 정답에 적용되는 문항은 체력 30% 이하의 despair 4개와 호위 중의 promise 1개, 모두 5개뿐이라 보정 규칙은 거의 검증되지 않았다.
3. **정답이 규칙 표에서 나온다.** Intent 에 구조적으로 유리하고, 표 자체가 어둠의 감정을 제대로 나타내는지는 검증하지 않았다.
4. **기준선 비교가 비대칭이다.** 기준선은 `mood_delta` 의 ±5 안을 0 으로 보고, 다른 조건과 정답은 ±2.5 안을 0 으로 본다. 프롬프트도 조건마다 다르다(기준선은 여섯 감정 상태·의도 목록이 없다).
   비교는 균형 방향 하나로 줄였고, 감정별 비교는 Intent·Direct 사이에서만 했다.
5. **학습 대사 복제 지표에는 기준이 여럿이다.** 학습 파일 한 개와 비교하는데, 요약 파일의 값은 실행 시점의 파일을 기준으로 한다. 이 보고서는 모델이 학습한 판을 기준으로 다시 맞췄다(표 1·6 의 각주).
   보강 전 모델이 보강 전 파일(`e79ac07`)로 학습했다는 것은 커밋 시각(03:13)과 학습 폴더 시각(Intent 05:38, Direct 07:02)으로 추정한 것이다. 문자열이 완전히 같은 경우만 세므로 조금 바꾼 복제는 놓친다.
   Legacy 의 0% 는 의미가 없다.
6. **반복 3회는 샘플링 오차만 보여 준다.** 모델은 조건마다 1번 학습했고, 표준편차에 학습 변동은 들어 있지 않다. Intent 의 의도 오류는 3회 모두 틀린 18문항이 대부분이라 반복을 늘려도 오차는 줄지 않는다.
   보강 전과 v2 의 0.6%p 차이를 학습 변동과 구분할 수 없다.
7. **실행 경로가 섞여 있다.** Direct 2·3회차와 v2 3회는 게임 서버 경로로 돌렸다. 함수·온도·문법·컨텍스트는 같지만 서버 인스턴스가 다르다.
   Direct 의 균형 방향이 1회차(경로 A) 85.9%, 2·3회차(경로 B) 82.8%·84.0% 로 나왔는데, 경로 영향인지 단순 변동인지 이 자료로는 가를 수 없다. 응답 시간 비교도 같은 이유로 참고용이다.
8. **측정하지 못한 것.** 감정 안정성(연속 대화에서의 출렁임), 대사와 감정의 일치도, 게임 안에서 몸 강탈이 어떻게 달라지는지, 대사 품질 채점은 이번 결과에 없다. 모든 문항은 한 번의 발화이므로 대화 한 번의 누적 ±20 제한도 평가하지 않았다.

## 7. 결론과 다음 단계

초안 라벨 기준으로, 의도 형식이 균형 방향 일치 90.6 ± 0.9% 로 직접 형식(84.3 ± 1.5%)과 기준선(66.3 ± 1.6%)보다 높았고, 이 차이는 반복 3회의 편차보다 컸다.
오류는 반어·혼합 문장과 일부 문항에 몰려 있다. 확정된 결론은 라벨 검수 뒤에 다시 집계한 값으로 써야 한다.

1. 163문항을 검수하고 `reviewed` 를 고친 뒤, 검수한 문항만으로 같은 집계를 다시 한다(설계 11절).
2. 감정 안정성과 대사-감정 일치도를 연속 대화로 잰다(설계 1절의 나머지 두 기준).
3. v2 를 게임 기본 모델로 바꿀지는 대사의 자연스러움을 확인한 뒤 정한다.
