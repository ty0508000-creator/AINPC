# 구현 내용 정리 (주차별)

캐릭터 내부의 또 다른 인격 '어둠(Darkness)'과 NPC 대화를 중심으로,
로컬 LLM 기반의 상호작용 시스템을 주차별로 구현하였다.

---

## 1주차 : AI 학습 (어둠 인격 LLM 파인튜닝)

-학습 목표
캐릭터 내부의 또 다른 인격인 '어둠(Darkness)'이 몸의 제어권을 두고 플레이어와 협상·위협·회유하는 대화를 수행하도록, 로컬에서 구동 가능한 소형 LLM을 파인튜닝하였다. 출력은 게임 로직이 곧바로 파싱할 수 있도록 항상 `{"dialogue":"대사","mood_delta":0}` JSON 형식을 따르게 하여, **대사 생성**과 **감정 수치(mood_delta, -20~+20) 판정**을 한 번의 추론으로 동시에 수행하도록 설계하였다.

-학습 데이터 생성 (gen_data.py)
규칙 기반 조합형 생성기: 수작업 라벨링 대신 상황(HP·기분 게이지·적 수·제어자)을 무작위로 조합하는 생성기를 구현하여 약 1,000개의 멀티턴 대화 샘플을 자동 생성하였다.
런타임 정합성: 학습 데이터의 system 프롬프트를 게임 런타임(InnerVoiceManager)에서 실제 사용하는 프롬프트와 동일한 형식으로 맞춰, 학습과 추론 간 분포 불일치를 최소화하였다.
카테고리 기반 일관성: 플레이어 발화를 의미에 따라 항복·반항·달램·거래·모욕·협력 등 12개 카테고리로 분류하고, 카테고리마다 (발화 ↔ 어둠 반응 ↔ mood_delta 범위)를 짝지어 대사 톤과 감정 수치의 방향성이 항상 일관되게 라벨링되도록 하였다.
재현성: 전체 대화를 문자열 키로 비교해 중복을 제거하고 시드(seed=42)를 고정하여 재현 가능하게 하였다.

-모델 및 학습 (train.py)
QLoRA 경량 학습: 무료 GPU(Colab T4) 환경에서도 8B급 모델을 학습할 수 있도록, 베이스 모델(Meta-Llama-3.1-8B-Instruct)을 4bit로 로드하고 저랭크 LoRA 어댑터만 학습하는 QLoRA 기법을 적용하였다.
주요 설정: LoRA rank/alpha 16, 4 epochs, learning rate 2e-4(cosine), 유효 배치 8, max sequence length 2048, Unsloth + TRL(SFTTrainer) 프레임워크를 사용하였다.

-배포 (GGUF → Ollama → LLMUnity)
오프라인 구동: 학습된 어댑터를 병합한 뒤 GGUF(Q4_K_M) 포맷으로 양자화하여, 외부 API 의존 없이 완전 오프라인 로컬 추론이 가능하도록 하였다.
연동 경로: 변환된 모델을 Modelfile로 Ollama에 등록(`ollama create inner-voice`)하고, 유니티의 LLMUnity가 이를 로드하여 대화 추론을 수행한다. Modelfile에는 system 프롬프트와 추론 파라미터(temperature 0.85 등)를 고정해 캐릭터 톤의 일관성과 출력 안정성을 확보하였다.

## 2주차 : AI 통제권 강탈 (제어권 전환 시스템)

-개념
캐릭터는 하나의 몸을 플레이어와 AI 인격(어둠)이 공유한다. 평소에는 플레이어가 조작하지만 특정 조건이 충족되면 AI가 조작권을 강탈하여 스스로 캐릭터를 움직이고 전투하며, 이는 1주차의 LLM 대화 결과(기분 게이지 변화)와 직접 연동되는 핵심 메커니즘이다. 시스템은 책임 분리를 위해 조건 판정(MoodSystem)·상태 중계(ControlManager)·행동 수행(AIController) 세 컴포넌트로 구성하였다.

-강탈/반환 조건 (MoodSystem.cs)
전투 한정 강탈: 기분 게이지(0~100)는 LLM 대화 결과와 게임 상황에 따라 변동하며, 강탈은 무조건 일어나지 않고 '전투 중'일 때로 한정하였다. 강탈은 `전투 중 && 기분 ≤ 20`, 반환은 `전투 종료 || 기분 ≥ 70` 조건에서 발생한다.
실시간 전투 감지: CombatWatch 코루틴이 0.5초 간격으로 일정 반경 내 적 레이어의 존재를 검사해 전투 상태를 갱신하고, 전투 진입·이탈 순간마다 조건을 즉시 재평가하여 전투가 끝나면 기분이 낮아도 곧바로 제어권을 플레이어에게 반환하도록 하였다. 이로써 강탈을 '위기의 순간에만 일어나는 긴장된 사건'으로 만들었다.

-상태 중계 (ControlManager.cs)
느슨한 결합: MoodSystem의 강탈/반환 이벤트를 구독해 제어 주체 플래그(IsPlayerControlled)를 갱신하고 동일 이벤트를 다시 발행한다. 이 이벤트 중계 구조 덕분에 플레이어 입력 처리·AI 행동·연출 효과 등 여러 시스템이 서로를 직접 알 필요 없이 제어권 전환에 반응할 수 있도록 하였다.

-AI 자동 행동 (AIController.cs)
유능한 자동 전투: 강탈이 발생하면 가장 가까운 적을 적이 죽거나 도망칠 때까지 연속 추격·공격하며, 거리에 따라 근거리는 일반 공격, 원거리는 대시 공격, 그 외는 걸어서 접근하도록 분기하였다. 중첩 코루틴을 `yield return`으로 호출해 제어권 회복 시 모든 하위 동작이 한 번에 중단되도록 하여 코루틴 누수를 방지하였다.
제어권 상실의 대가: AI는 강하지만 몸을 사리지 않아, 적 접촉 범위 안에서는 주기적으로 자신에게 피해를 입어 HP가 깎인다. 이를 통해 'AI에게 몸을 맡기면 적은 잘 처치하지만 대신 몸이 상한다'는 위험-보상 트레이드오프를 게임 메커니즘으로 구현하였다.

-연출 (TakeoverEffect.cs)
체감되는 사건: 제어권이 넘어가거나 회복되는 순간을 플레이어가 명확히 인지하도록 적색 화면 플래시, 카메라 흔들림, 프리셋 대사, 효과음을 트리거하여, 단순한 내부 상태 변화가 아니라 체감되는 사건으로 전달하였다.

## (주차: 추후 지정) : NPC 자동 대화 활성화

-트리거 기반 상호작용 (NpcInteraction.cs)
자동 활성화: 플레이어가 NPC의 일정 범위(Collider Area) 내로 진입 시, 별도의 조작 없이 대화창이 자동으로 활성화되도록 구현하여 사용자 편의성 및 몰입감을 높였다. 플레이어와 NPC 사이의 거리가 멀면 대화창이 비활성화되며, NPC에게 근접하게 되면 대화창이 열리게 된다.
구현 방식: 각 NPC에 트리거(Trigger)로 설정된 2D 콜라이더를 부착하고, 진입(OnTriggerEnter2D) 시 NPC의 이름·성격 정보와 함께 DialogueManager.OpenDialogue를 호출해 대화창을 열고, 이탈(OnTriggerExit2D) 시 CloseDialogue를 호출해 닫는다. 상태 플래그로 중복 호출을 방지하고, 콜라이더·트리거 미설정 시 에디터 경고를 출력해 설정 실수를 예방하였다.

## 7주차 : UI 시스템 구현 및 1차 중간 점검

-UI 설계
계층적 UI 구조(Hierarchy Optimization): DialogueCanvas 내부에 DialoguePanel을 부모 오브젝트로 두어, 대화 시작/종료 시 패널의 활성화 상태(SetActive)를 조절하는 것만으로 전체 UI를 효율적으로 제어하도록 설계하였다.
시각적 일관성: 2D 픽셀 아트 스타일의 게임 분위기를 저해하지 않도록 반투명한 그레이톤 패널을 채택하였으며, 플레이어의 시선 이동을 고려하여 좌측 하단 대사창 - 우측 전송 버튼의 직관적인 배치를 적용하였다.

-사용자 중심의 입력 시스템 (UX)
실시간 텍스트 피드백: 플레이어가 입력한 내용은 TMP_InputField를 통해 즉각적으로 표시되며, 전송 시 NPC의 이름(예: 스미스)과 함께 답변이 상단에 출력되어 실제 메신저를 사용하는 듯한 연속적인 대화 경험을 제공한다.
상태 인지 디자인: AI가 답변을 생성하는 동안에는 전송 버튼을 비활성화하고 "생각 중..."이라는 텍스트를 노출하여, 시스템이 작동 중임을 플레이어에게 명확히 인지시킨다.

## 8주차 : 로컬 LLM 구동을 위한 Ollama 설치 및 경량화 모델(Llama-3-8B) 적용

-로컬 LLM(Local LLM) 도입 배경
보안 및 독립성: 외부 API(OpenAI 등)를 사용하지 않고 로컬 환경에서 모델을 구동함으로써, 인터넷 연결 없이도 동작 가능한 독립적인 게임 환경을 구축하였다.
비용 효율성: 지속적인 API 호출 비용 발생 문제를 해결하기 위해, 사용자 기기의 자원을 활용하는 로컬 구동 방식을 채택하였다.
방대한 자료 및 커뮤니티 생태계: 글로벌 커뮤니티에 공개된 수많은 양자화 모델과 최적화 라이브러리, 풍부한 구현 사례를 바탕으로 학생 수준에서도 고성능 AI 시스템을 안정적으로 구축할 수 있는 환경을 활용하였다.

-Ollama 설치 및 인프라 구성
프레임워크 선정: 다양한 LLM을 간편하게 관리하고 서빙할 수 있는 오픈소스 도구인 Ollama를 설치하였다.
유니티 연동(LLMUnity): Ollama 서버와 유니티 엔진 간의 통신을 위해 LLMUnity 패키지를 도입하였으며, 이를 통해 스크립트 기반의 비동기 채팅 시스템을 완성하였다.
모델 선정: Meta에서 공개한 오픈소스 모델인 Llama-3-8B를 채택하였으며, 해당 모델은 80억 개의 파라미터를 가지고 있어 한국어 이해 능력이 뛰어나고 NPC 대화에 적합한 성능을 가지고 있다고 판단해 선정하게 되었다.

-유니티 내 LLM 기본 설정
유니티 인스펙터(Inspector) 창에서 LLMUnity의 모델·서버 파라미터를 연결·설정하여, 게임 실행 시 로컬 모델이 자동으로 로드되고 대화 시스템이 이를 호출하도록 구성하였다.
