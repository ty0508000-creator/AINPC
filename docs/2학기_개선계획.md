## 3. 해결 방안 요약

### A. 즉시 (반나절)
- A-1 `EditorBuildSettings.asset`에 Test.unity GUID 추가 (+ 에디터에서 Main.unity로 리네임)
- A-2 `mood_delta` 파싱 단계에서 `Mathf.Clamp(-20, 20)`
- A-3 raw 폴백 제거 → `parseOk` 플래그 도입, 화면엔 페르소나 폴백 대사("흠...", "...")
      로그엔 실패로 기록 (화면과 로그 분리)
- A-4 저장 경로를 `Application.persistentDataPath` 절대경로로. 최초 실행 시 StreamingAssets 시드 복사
- I 문서 정정 (Ollama 서술)

### B. 배포 (2주차 의사결정)
**권장: 3B 단일 모델 통합 재학습** (~2GB / RAM 3~4GB / 응답 2~3배 빠름)
- 베이스를 `Llama-3.2-3B-Instruct` 또는 `Qwen2.5-3B-Instruct`로 변경
- `gen_data.py`에 Mr.Smith 카테고리 추가 → 모델 1개로 두 인격 처리, 서버 2개→1개
- 어차피 7주차에 재학습 예정이므로 추가 비용 사실상 0
- 3주차에 시험 학습 1회로 품질 확인 후 7주차 본 학습 결정. 미달 시 8B 단일 통합(5GB)으로 후퇴

### C. JSON 안정화 (5주차, 반나절)
GBNF grammar를 `Start()`에서 1회 설정. 재요청은 안전망으로만 유지.
```
root   ::= "{" ws "\"dialogue\":" ws string "," ws "\"mood_delta\":" ws int "," ws "\"action_intent\":" ws intent ws "}"
string ::= "\"" char* "\""
char   ::= [^"\] | "\\" ["\/bfnrt]
int    ::= "-"? [0-9] [0-9]?
intent ::= "\"aggressive\"" | "\"cautious\"" | "\"defensive\""
ws     ::= " "?
```
문법은 구조만 강제하므로 A-2 클램프는 유지. 적용 전후 파싱 실패율을 측정해 보고서 근거로 남길 것.

### D. 기억 메타데이터 (6주차)
`MemoryEntry { key, text, eventType, importance, timestampTicks, recallCount }`
- 중요도는 LLM에 묻지 말고 규칙으로 산출 (배신/약속/협력 1.0, 거래/모욕 0.7, 질문 0.4, 잡담 0.2)
  → `gen_data.py`의 12개 카테고리 체계 재사용. LLM 출력에 `event_type` 필드를 넣으면 분류도 공짜
- 점수 = w1*(1-dist/2) + w2*importance + w3*exp(-ageDays/halfLife)  (예: 0.5/0.3/0.2)
- 하드 컷(distance > 1.0) + 소프트 컷(Score < minScore) → **0건이면 "기억 없음" 조건이 자연 재현**
- 가중치는 인스펙터 노출 → 12주차에 가중치별 정확도 그래프가 곧 실험 결과

### E. 기억→행동 (10주차)
`action_intent`가 기억과 행동을 잇는 다리.
`CombatProfile { moveSpeedMul, engageRange, recklessInterval, recklessDamage, useDash, retreatHpRatio }`
`AIController.StartAI()`에서 `ControlManager.PendingIntent`로 프로필 선택.
기존 `BehaviorLoop`/`RecklessLoop`의 하드코딩 상수를 프로필 필드로 대체 (구조 재설계 아님).

### F. 통합 로그 (3주차)
`TurnLogger` 정적 클래스로 분리, InnerVoiceManager에서도 호출. 한 턴 = 한 행:
```
timestamp, scene, speaker, turn_index, player_input, memory_condition,
retrieved_keys, retrieved_distances, retrieved_scores, retrieved_count,
llm_response_time_s, timeout, parse_ok, retry_count,
mood_before, mood_delta_raw, mood_delta_applied, mood_after,
action_intent, control_state, combat_profile, hp, enemy_count, fps_avg, mem_mb
```
`retrieved_keys`가 있으면 정답 집합과 대조해 precision/recall을 사후 계산 가능.

### G. 완성도
- G-1 오디오: CC0 음원 7개(타격2/대시1/강탈1/복귀1/BGM2) 넣고 슬롯 연결. 코드는 이미 있음
- G-2 게임오버/리스폰. 죽음을 `eventType="죽음", importance=1.0`으로 기억에 남기면 콘셉트에 부합
- G-3 내면 대화 멀티턴화. 종료조건: 나가기 / 5턴 / Mood≤강탈임계(결렬, 즉시 강탈) / Mood≥반환임계(성공)
- G-4 `PlayerSaveData`에 mood 추가
- G-5 `autoSaveOnRemember=false` + 씬전환/종료/30초 주기 저장 (12주차 성능 측정 전 필수)

### H. 리팩터링 (3주차)
`MemoryManager` + `MrSmithLongTermMemory` → 공통 `NpcMemory`로 통합.
`DialogueManager.IsMrSmith()` 하드코딩 제거, `NPCInteraction`이 자기 메모리/프롬프트 템플릿 보유.
**D·E가 이 정리 위에 올라가므로 순서 준수. 프리팹 스크립트 참조가 걸려 있어 Unity MCP 연결 상태에서 진행 권장.**
