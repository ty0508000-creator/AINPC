# 감정 설계와 튜닝 과정

작성일: 2026-11-16 · 용도: 개발 과정과 논문 작성 근거 정리

> 이 문서는 기존 프로젝트 기록을 재구성한 것이다. 실험 수치는 해당 문서에 기록된 값이며, 이번 문서 작성 중 모델 학습이나 실험을 다시 실행하지 않았다. 특히 6감정 실험은 **사람이 검수하지 않은 정답 라벨을 사용한 예비 결과**다. 설계 목표, 구현 및 실험 기록을 구분해 읽는다.

## 1. 연구의 흐름

이 프로젝트는 플레이어와 내면 인격 ‘어둠’이 하나의 몸을 공유하는 게임이다. 플레이어의 말과 게임 상황이 어둠의 상태에 영향을 주고, 그 상태는 대사와 전투 중 조작권 전환으로 이어지도록 설계했다. NPC와의 호감도는 어둠의 감정과 별도다.

| 시기 | 감정·대화 모델의 변화 | 목적과 근거 |
|---|---|---|
| 초기 | 단일 감정 수치 `Mood`와 `mood_delta`, Llama 기반 어둠 모델 | 대사 생성과 수치 판정을 한 번의 추론으로 연결. [기존 논문 정리](논문_구현내용.md) |

| 2026-10-16 | 내면·NPC 데이터를 보강하고 Qwen3-4B와 Kanana를 각각 학습·비교 | 말투 분리, 대사 다양성, 기억 활용과 경량화를 함께 고려. [연구 근거 8절](RESEARCH_EVIDENCE.md) |

## 2. 기존 단일 감정 설계

### 2.1 하나의 수치와 제어권

기존 `Mood`는 0~100의 감정 수치로, 어둠과의 관계 및 복수에 잠식되지 않은 정신적 균형을 하나의 축으로 표현했다. 내면 대화의 LLM 응답에는 대사와 `mood_delta`가 함께 들어갔고, 게임이 변화량을 적용했다. 높은 값은 상대적으로 안정된 상태, 낮은 값은 복수에 물들어 불안정한 상태로 해석했다.

```json
{"dialogue":"대사", "mood_delta":-8}
```

기존 설계에서 시작값은 50이며, 전투 중 수치가 20 이하이면 어둠이 제어권을 가져가고 전투가 끝나거나 수치가 70 이상이면 플레이어에게 반환했다. 수치 하나로 대화와 전투를 연결하기는 쉬웠지만, 같은 낮은 값이 분노·두려움·불신 중 무엇을 뜻하는지 구분하기 어려웠다. 이후 6감정 설계는 이런 원인을 나누고, 관계에 따라 협력 요청과 강제 개입을 구분하려 했다. 구체적인 과거 조건은 [기존 논문 정리 2주차](논문_구현내용.md)와 Git의 감정 개편 전 `MoodSystem.cs`를 참고한다.

### 2.2 초기 Llama 기반 튜닝

기존 기록에 따르면 Meta-Llama-3.1-8B-Instruct를 기반으로 어둠의 협상·위협·회유 대사와 `mood_delta`를 함께 출력하도록 QLoRA 학습을 진행했다. 플레이어 발화를 항복·반항·달램·거래·모욕·협력 등 범주로 나누고, 상황과 응답을 조합해 약 1,000개의 멀티턴 대화를 생성했다. 기록된 설정은 4bit 로딩, LoRA rank와 alpha 16, 4 epoch, 학습률 2e-4, 유효 배치 8, 최대 길이 2,048이다. 병합한 모델을 Q4_K_M GGUF로 변환해 LLMUnity의 LlamaLib을 통해 로컬에서 사용했다.

이 내용은 당시의 기록이다. 기존 문서는 학습 프롬프트가 게임과 같다고 설명하지만, **2026-10-15의 후속 점검은 실제로 프롬프트와 대화 구조가 달랐다고 확인했다.** 따라서 과거 문구를 현재 검증된 사실로 그대로 옮기지 않는다.

### 2.3 기존 모델과 데이터의 문제

[연구 근거 6절](RESEARCH_EVIDENCE.md)에 기록된 점검 결과는 다음과 같다.

- 옛 데이터의 2,338턴에 서로 다른 대사는 186개였고, 특정 대사가 44번 반복됐다.
- 학습 시 프롬프트에 게임의 배경·기억·사건 구성이 충분히 반영되지 않았고, 학습은 멀티턴이었으나 당시 게임의 응답 요청은 한 턴씩 처리됐다.
- 같은 범주의 질문과 답을 무작위로 짝지어 내용이 어긋나는 경우가 있었고, NPC 학습 샘플은 없었으나 같은 모델이 NPC 대사도 생성했다.
- 44문항 평가에서 기존 `darkness` 모델은 방향 판정은 높았지만, 학습 대사를 그대로 반복하고 NPC와 스미스에게도 어둠의 말투를 사용하는 문제가 관찰됐다. 온도 0.6 조건에서 형식은 44/44였으나 변화량 범위 ±20을 넘은 출력은 9/44였다. 게임 쪽 제한과 모델 원출력은 구별해야 한다.

이 결과는 단일 평가 세트에서의 관찰이며, 반복 대사나 말투 혼입의 정도를 모든 대화에 일반화할 수는 없다.

별도의 2026-10-13 구조화 출력 실험에서는 짧은 입력 12개를 반복해 NPC·내면 응답 총 48개를 비교했다. JSON grammar를 끈 조건의 엄격한 파싱 성공은 44/48, 켠 조건은 48/48이었다. 반면 `mood_delta`의 ±20 초과는 두 조건 모두 10/48이었다. 형식 제한과 수치 범위 제한은 별개라는 관찰이지만, 소표본이고 실제 게임보다 짧은 프롬프트를 사용했다.

## 3. 단일 감정 단계의 데이터 보강과 모델 선택

### 3.1 데이터 구성과 학습 방법

2026-10-15 기록에서는 게임 코드가 내보낸 프롬프트 틀에 상황을 채우도록 학습 데이터를 다시 구성했다. 한 샘플은 시스템·사용자·어시스턴트의 한 턴이며, 내면 1,500개, 일반 NPC 450개, 스미스 200개로 총 2,150개다. 내면에는 첫 마디 522개와 플레이어 발화에 대한 대답 978개가 포함됐다. 특정 질문과 관련된 답을 묶고, HP·적 수·제어 주체·기억·사건을 상황에 반영했다. 평가 입력 44개는 학습에 넣지 않도록 검사했다.

2026-10-16에는 이 데이터로 Qwen3-4B-Instruct-2507과 Kanana-1.5-2.1B를 각각 학습했다. 기록상 Windows 환경에서 QLoRA 4bit, rank 16, 2 epoch, 응답 토큰에만 손실을 적용했고 모델별 chat template을 사용했다. 어댑터 병합 후 Q4_K_M GGUF로 변환했다. 이 수치는 **당시 단일 감정 데이터 학습**의 설정이며, 6감정 모델의 모든 학습 실행에도 그대로 적용됐다고 단정하지 않는다.

### 3.2 모델 비교와 Qwen 선정

아래는 [연구 근거 8절](RESEARCH_EVIDENCE.md)에 기록된 당시 결과다. 방향 일치는 44문항을 세 번 평가한 총 132회 기준이고, 기억 활용은 15문항을 세 번 평가한 45회 기준이다. 세 모델의 기반과 학습 데이터가 서로 달라 모델 구조나 튜닝 하나만의 효과로 해석할 수 없다.

| 지표 | 기존 darkness | Kanana 2.1B 학습 모델 | Qwen3-4B 학습 모델 |
|---|---:|---:|---:|
| Q4_K_M 크기 | 4.9GB | 1.4GB | 2.5GB |
| `mood_delta` 방향 일치 | 90% | 98% | 98% |
| ±20 범위 초과 | 22% | 0% | 0% |
| 서로 다른 대사 | 55/132 | 91/132 | 110/132 |
| 해당 새 학습 대사와 완전 일치 | 비교 대상 아님 | 51/132 | 31/132 |
| 기억 블록의 사실 활용 | 3/45 | 22/45 | 30/45 |
| 전체 응답 시간 GPU / CPU 전용 | 0.70 / 5.84초 | 0.27 / 1.79초 | 0.45 / 2.78초 |

당시에는 Qwen의 대사 다양성과 기억 활용을 고려해 게임 대화 모델로 선택했다. 내면과 NPC가 모델을 공유하되 요청별 시스템 프롬프트로 인격을 구분하는 방식이다. CPU 전용 수치는 실제 목표 노트북의 내장 그래픽 측정이 아니며, 대사 품질 판단은 사람의 읽기 평가이고 표본이 작다. 기억 활용은 프롬프트에 넣은 사실의 핵심어가 응답에 나왔는지 확인한 것으로, 기억 검색 시스템 전체의 품질과 같지 않다.

10월의 방향 일치 98%와 뒤의 11월 Legacy 균형 방향 일치 66.3%는 평가 문항, 정답 및 지표가 달라 직접 비교해 성능 하락이라고 해석하면 안 된다. 11월 Legacy는 초기 darkness가 아니라 단일 Mood 단계의 Qwen 학습 모델을 사용했다.

## 4. 6감정 설계

### 4.1 상태의 분리

6감정 설계는 하나의 수치 대신 분노·복수심·슬픔·두려움·신뢰·냉정을 각각 0~100으로 표현한다. 다음은 [설계 문서 4절](superpowers/specs/2026-11-14-emotion-hexagon-design.md)의 기준이다.

| 감정 | 역할 | 시작·변화 방식 |
|---|---|---|
| 분노 | 위협에 대한 공격적 반응 | 시작 30, 전투 밖에서 기준값으로 복귀. 코드 이벤트와 대화 규칙으로 변화 |
| 복수심 | 보스에게 향하는 장기적 동기 | 처치한 보스 수로 `20 + 16 × 보스 수`를 계산, 최대 100 |
| 슬픔 | 과거의 상처 | 시작 40, 자동 복귀하지 않으며 이야기·코드 이벤트로 변화 |
| 두려움 | 상실과 위기에 대한 반응 | 시작 20, 전투 밖에서 기준값으로 복귀. 코드 이벤트와 대화 규칙으로 변화 |
| 신뢰 | 플레이어와 어둠의 관계 | 시작 30, 자동 복귀하지 않으며 코드 이벤트와 대화 규칙으로 변화 |
| 냉정 | 판단과 행동의 안정성 | 시작 50, 전투 밖에서 기준값으로 복귀. 코드 이벤트와 대화 규칙으로 변화 |

복수심과 슬픔은 대화 LLM이 직접 움직이지 않는다. 분노·두려움·신뢰·냉정 네 감정도 모델이 게임 수치를 직접 수정하는 것이 아니라, 모델의 의도·강도 출력에 게임 규칙을 적용해 변화시킨다.

### 4.2 감정과 게임 행동

설계상 어둠의 압박은 `clamp(max(분노, 두려움) + 0.2 × 슬픔, 0, 100)`으로 계산한다. 전투 중 압박이 70 이상일 때 신뢰가 50 이상이면 몸을 맡아도 되는지 요청하고, 50 미만이면 강제 개입한다. 전투 종료 또는 압박 40 이하에서 반환한다. 분노와 두려움의 우세에 따라 전투 성향을, 신뢰와 강한 감정에 따라 대사 어조를 정한다. 복수심은 보스 우선 공격과 연결하도록 설계했다.

이 구성은 **감정 수치와 행동 규칙의 설계**를 설명한다. 실제 플레이에서 전환이 자연스러운지, 플레이어가 원인을 이해하는지는 별도의 플레이 검증이 필요하다.

## 5. 6감정 LLM 튜닝과 출력 방식

### 5.1 세 가지 비교 조건

| 조건 | LLM 출력 | 감정 변화 판정 | 용도 |
|---|---|---|---|
| Legacy | `dialogue`, 단일 `mood_delta` | 모델이 수치 출력 | 기존 방식 기준선 |
| Direct (A) | `anger`, `fear`, `trust`, `calm`, `dialogue` | 모델이 네 변화량을 직접 출력 | 비교 실험 |
| Intent (C) | `intent`, `intensity`, `dialogue` | 모델이 의도·강도를 분류하고 게임 규칙 표가 변화량 계산 | 게임 기본으로 설계 |

Intent의 예시는 `{"intent":"soothe","intensity":2,"dialogue":"…그 말, 예전에도 들었다."}`다. JSON 문법으로 의도를 정해진 10개, 강도를 1~3으로 제한하며 판단 필드를 대사보다 먼저 생성한다. 의도는 맡김·달램·설득·약속·거부·모욕·나약함·복수 선동·과거 질문·그 외다. 이 방식은 모델이 실제 감정을 느낀다는 뜻이 아니라, 발화를 분류해 게임에서 해석 가능한 규칙에 연결한다는 뜻이다.

### 5.2 의도에서 감정으로

규칙 표는 평가 이론과 OCC를 참고해 어둠의 목표에 발화가 도움이 되는지, 위협이 되는지 등을 설계자가 해석한 것이다. **이론을 참고한 설계라는 사실과 표의 타당성이 실험으로 검증됐다는 주장은 다르다.** 강도 1 기준 값은 다음과 같다. 빈칸은 변화 없음이다.

| 의도 | 분노 | 두려움 | 신뢰 | 냉정 |
|---|---:|---:|---:|---:|
| 맡김 `entrust` | — | -3 | +4 | — |
| 달램 `soothe` | -4 | — | +2 | +3 |
| 설득 `reason` | -2 | — | — | +4 |
| 약속 `promise` | — | — | +5 | — |
| 거부 `defy` | +3 | — | -4 | — |
| 모욕 `insult` | +6 | — | -3 | — |
| 나약함 `despair` | — | +4 | -2 | -2 |
| 복수 선동 `vengeance` | +4 | — | — | -3 |
| 과거 질문 `ask` | — | — | — | +1 |
| 그 외 `neutral` | — | — | — | — |

기본 변화량에 강도를 곱하고 필요한 상황 보정을 적용한다. 예를 들어 강도 2의 달램은 분노 -8, 신뢰 +4, 냉정 +6이다. 체력 30% 이하의 나약함은 두려움에 1.5배, 하연 호위 중 약속은 신뢰에 1.5배 보정한다. 내면 대화를 열고 닫는 동안 감정별 누적 변화는 ±20으로 제한하도록 설계했다.

### 5.3 데이터와 모델 학습

게임 프롬프트 틀을 내보낸 뒤 `Training/gen_data.py`가 상황과 대사를 조합해 `train_intent.jsonl`, `train_direct.jsonl`을 생성한다. 두 형식은 같은 샘플에서 만들어지며 Direct의 정답 수치는 의도·강도에 동일한 게임 규칙 표를 적용해 얻는다. 프롬프트에는 여섯 감정과 현재 상황이 포함되고, 대사는 의도 및 어조에 맞춰 구성한다. 평가 입력은 학습 데이터와 겹치지 않도록 검사한다.

현재 학습 파일에는 형식별로 각각 3,050개가 있으며 내면 2,400개(첫 마디 751개, 응답 1,649개), 일반 NPC 450개, 스미스 200개로 구성된다. 현재 파일 기준 내면의 서로 다른 응답은 798개다. 이는 현 파일의 집계이며 모든 과거 학습에 이 버전이 사용됐다는 뜻은 아니다. 평가 입력과 학습 사용자 발화의 문자열 완전 일치는 0건이지만 의미가 비슷한 문장까지 배제했음을 뜻하지는 않는다.

평가 보고서에 따르면 두 모델은 Qwen3-4B 기반으로 학습하고 Q4_K_M으로 양자화했다. 현재 `train_local.py`의 기본값은 4bit QLoRA, rank 16, 2 epoch, 학습률 2e-4, 유효 배치 8이며 응답 토큰에만 손실을 적용한다. **각 실험의 실제 실행 인자와 학습 로그는 확인하지 못했으므로 현재 기본값을 당시 실행 설정으로 단정하지 않는다.**

Direct는 비교용, Intent는 게임 기본 방식으로 설계됐다. 현재 `Assets/Resources/LLMServices.prefab`은 보강 전 Intent 모델 경로를 지정하지만, 해당 GGUF와 지정된 임베딩 모델 파일은 현재 모델 폴더에서 확인되지 않았다. 후속 Intent v2는 평가 보고서 작성 당시 게임에 연결하지 않았다고 기록되어 있다. 이번 문서 작성에서는 실제 게임 대화를 실행하지 않았다.

## 6. 6감정 비교 실험: 예비 결과

### 6.1 평가 조건과 지표

[감정 평가 보고서](EMOTION_EVAL_REPORT.md)는 163문항의 동일한 평가 세트를 조건별로 세 번 실행한 결과를 정리한다. 문항마다 상황과 여섯 감정 상태를 정했으며, 한 문항은 대화 이력이 없는 단일 발화다. 온도 0.6, JSON 문법, 컨텍스트 4,096, GPU 층 99를 사용했다. 일부 Direct와 v2 실행은 평가용 서버의 네이티브 크래시 때문에 게임 서버 경로로 실행됐다.

공통 지표인 균형은 `신뢰 + 냉정 - 분노 - 두려움`이다. 예측한 변화 방향이 초안 정답의 증가·유지·감소와 일치하는 비율을 계산했다. Legacy는 네 감정을 내지 않으므로 `mood_delta`의 부호를 비교했으며, 중립으로 보는 임계값도 조건에 따라 달랐다. Intent와 Direct는 추가로 감정별 방향과 평균 절대 오차를 비교했다. Intent에는 의도 정확도와 macro-F1을 사용했다.

**정답 의도·강도는 Claude가 작성한 초안이고 163문항 모두 사람의 검수를 받지 않았다.** 정답 감정 변화도 그 라벨에 게임의 규칙 표를 적용해 만들었다. 설계 문서는 검수된 문항만 결과에 쓰도록 정했으므로, 아래 값은 논문에 확정 결과로 사용할 수 없는 예비 관찰이다. 결과의 CSV와 요약이 있던 `VerificationResults/Research/`는 현재 작업 폴더에서 확인되지 않아 이번에는 보고서의 기록을 재집계하지 못했다.

### 6.2 방식별 결과

| 지표 | Legacy | Direct | Intent |
|---|---:|---:|---:|
| 균형 방향 일치, 평균 ± 표준편차 | 66.3 ± 1.6% | 84.3 ± 1.5% | 90.6 ± 0.9% |
| 세 회차의 일치 문항 수 / 163 | 105 · 109 · 110 | 140 · 135 · 137 | 148 · 149 · 146 |
| 형식 그대로 파싱 | 각 163/163 | 각 163/163 | 각 163/163 |
| Intent 의도 정확도 | — | — | 87.7 ± 0.6% |
| Intent macro-F1 | — | — | 0.875 ± 0.006 |

Intent는 이 초안 라벨 기준 평가에서 Direct보다 균형 방향 일치가 6.3%p 높았다. 네 감정 각각의 방향 일치도는 Intent가 90.6~95.1%, Direct가 82.0~89.6%였다. 파싱 성공은 grammar를 켠 조건의 결과여서 모델이 제약 없이 JSON을 얼마나 잘 작성하는지 나타내지는 않는다. 또한 정답이 Intent가 쓰는 규칙 표에서 생성되어 Intent에 구조적으로 유리하다. 따라서 이 비교는 **정해진 표의 결과를 재현하는 방식의 차이**를 보여줄 뿐, 표가 인물의 감정을 올바르게 표현하는지 입증하지 않는다.

오류 중 모욕을 달램으로 분류한 경우와 중립 발화를 나약함으로 분류한 경우가 눈에 띄었다. 반어와 여러 의도가 섞인 문장에서 어려움이 관찰됐으나 해당 문항 수가 적다. 강도를 정확히 맞힌 비율은 62.2 ± 0.9%, ±1 이내는 97.1 ± 0.4%였다. 예측 강도를 사후에 2로 고정했을 때 분노·신뢰의 평균 절대 오차가 각각 0.29, 0.36 커졌지만, 강도 없이 따로 학습한 모델과의 비교는 아니다.

### 6.3 대사 보강과 Intent v2

학습 대사와 출력이 글자까지 완전히 같은 비율이 높아, 맡김·달램·약속·거부의 응답 문장을 보강하고 다시 학습했다. 보고서에 따르면 샘플 수는 2,400개로 유지됐고 서로 다른 내면 대사는 666개에서 798개로 늘었다.

| 지표 | 보강 전 Intent | Intent v2 |
|---|---:|---:|
| 학습 대사 완전 일치율 | 30.3 ± 2.5% | 17.4 ± 0.4% |
| 의도 정확도 | 87.7 ± 0.6% | 87.1 ± 0.6% |
| 균형 방향 일치 | 90.6 ± 0.9% | 90.8 ± 0.0% |

완전 일치율은 각 모델이 학습한 판의 대사와 비교했다. 보강 전 학습 파일 판본은 기록 시각을 바탕으로 추정한 것이며, 일부 단어만 바꾼 유사 대사는 이 지표가 잡지 못한다. 약속의 재현율은 높아졌지만 다른 의도를 약속으로 분류하는 오류도 늘었다. v2의 자연스러움과 게임 연결은 보고서 당시 확인되지 않았다.

### 6.4 해석상 한계

1. 라벨 163개가 모두 미검수이며, 정답을 바꾸면 결과도 바뀐다.
2. 규칙 표 자체는 독립적으로 검증하지 않았고, 표 기반 정답은 Intent에 유리하다.
3. Legacy는 프롬프트와 중립 임계값이 달라 나머지 방식과 완전히 대칭적인 비교가 아니다.
4. 의도별 13~21문항으로 적고, 반어·상황 보정 등 하위 집단은 더 작다.
5. 모델은 조건별 한 번 학습했다. 반복 세 번의 표준편차는 주로 추론 반복의 변동이며 학습을 다시 했을 때의 변동을 나타내지 않는다.
6. 일부 실행의 서버 경로가 달라 응답 시간이나 결과 차이에 미친 영향을 분리할 수 없다.
7. 연속 대화의 감정 안정성, 대사와 감정의 일치도, 실제 제어권 전환의 체감, 대사 품질, 대화 누적 제한의 효과는 측정하지 않았다.

## 7. 논문 작성에 활용할 방향

### 7.1 연구 문제와 방법의 서술 예시

> 기존 시스템은 내면 인격의 상태를 단일 수치로 표현하여 대화와 조작권 전환을 연결했다. 그러나 동일한 수치만으로는 분노, 두려움, 신뢰 등 서로 다른 상태의 원인을 구분하기 어렵다. 이에 본 연구에서는 내면 인격의 상태를 여섯 감정으로 나누고, 플레이어 발화에서 의도와 강도를 분류한 뒤 규칙 표를 적용해 감정 변화를 계산하는 방식을 설계했다.

> 대화 모델은 상황과 감정 상태를 포함한 입력에 대해 의도, 강도, 대사를 JSON 형식으로 출력하도록 학습했다. 감정 변화량은 게임 로직에서 산출하며, 복수심과 슬픔은 이야기 사건에 의해 변화하도록 구분했다. 비교를 위해 기존 단일 수치 출력과 네 감정 변화량 직접 출력 조건도 구성했다.

위 문장은 설계와 기록을 바탕으로 한 **초안**이다. 실험 방법과 실제 적용 범위는 최종 원자료 및 실행 상태를 확인한 뒤 논문에 맞게 수정한다. OCC를 인용할 때는 실제 참고한 학술 문헌을 별도로 확인해 출처와 설계상의 적용 범위를 밝혀야 한다.

### 7.2 결과의 조심스러운 서술 예시

> 사람의 검수 전인 163문항의 초안 라벨을 기준으로 한 예비 평가에서, 의도 분류 방식의 균형 방향 일치율은 90.6 ± 0.9%, 직접 출력 방식은 84.3 ± 1.5%, 기존 단일 수치 방식은 66.3 ± 1.6%로 나타났다. 다만 정답 감정 변화가 의도 방식에 사용한 규칙 표에서 생성되었고 기준선의 프롬프트와 임계값이 달랐으므로, 이 차이를 감정 이해 능력의 일반적인 우위로 해석할 수 없다.

정식 논문 결과를 쓰기 전에는 라벨 검수와 재집계가 우선이다. 이후 연속 대화에서의 안정성·대사 일치도와 실제 게임 내 효과를 별도로 평가해야 한다. 정답 검수 기준, 검수자 수와 의견 불일치 처리, 데이터 구성, 학습 설정·시드, 모델별 평가 조건도 기록하면 재현과 해석에 도움이 된다.
