# 어둠의 6감정 시스템 설계

작성일: 2026-11-14

감정 수치 하나(`MoodSystem.Mood`)로 몸의 제어권을 정하던 구조를, 내면 인격 '어둠'의 여섯 감정으로 바꾼다.
LLM 은 플레이어 말의 **의도**를 판단하고, 감정 수치는 **해석 가능한 규칙 표**가 정한다.
게임 개편과 함께 보고서·논문에 쓸 비교 실험(기존 방식 대 새 방식, 출력 형식 A 대 C)을 같이 설계한다.

## 1. 왜 바꾸는가

- 수치 하나로는 "왜 몸을 빼앗았는가"가 설명되지 않는다. 화가 나서인지, 겁이 나서인지, 플레이어를 못 믿어서인지에 따라
  빼앗는 방식(요청/강제)과 싸우는 방식(학살/수호)이 달라야 인격이 산다.
- 지금 모델은 대사를 먼저 쓰고 `mood_delta` 를 뒤에 붙인다. 숫자가 대사에 맞춘 사후 합리화가 되고, 판단 근거를 추적할 수 없다.
- 보고서·논문: "LLM 이 의미를 판단하고 규칙이 감정을 정하는 방식"이 "LLM 이 수치를 직접 내는 방식"보다
  판단 정확도·감정 안정성·대사-감정 일치도에서 나은지를 같은 조건으로 측정한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 6감정(분노·복수심·슬픔·두려움·신뢰·냉정)이 제어권·전투 행동·대사에 실제로 반영된다.
- 신뢰에 따라 "물어보고 가져가기"와 "강제 탈취"가 갈린다.
- 하연 호위 의뢰에서 "동료를 또 잃을지 모른다"는 두려움이 생기고 수호형 전투로 이어진다.
- 내면 대화 모델을 새 형식으로 다시 학습하고, 기준선·A·C 를 같은 평가 세트로 비교한다.

**비목표 (이번 범위에서 생략)**
- 육각형 레이더 UI. 인게임 표시 방식이 정해지지 않았다. 이번에는 HUD 의 기존 감정 막대 자리에 임시로 "어둠의 압박"만 보인다.
- 상시 동료(파티) 시스템, 동행의 전투 AI, 동행 영구 사망.
- NPC·스미스 대화 형식 변경. 계속 `{"dialogue","mood_delta"}`(호감도)를 쓴다.
- 대사 품질의 LLM 채점 자동화. 대사는 CSV 로 내보내고 채점은 따로 한다.

**실패 조건 (돌아가도 실패인 것)**
- 모델이 한두 번 잘못 판단한 것만으로 몸 강탈이 일어난다.
- 감정이 대사와 따로 논다(달래는 말에 분노가 오른다고 판단하면서 대사는 누그러진다 등).
- NPC 대화 품질이 다시 학습한 뒤 눈에 띄게 떨어진다.
- 이전 세이브가 열리지 않는다.

## 3. 설정 (확정: A안)

어둠은 **천마에게 동료를 모두 잃은 과거의 자신**이다. 그날 이후 주인공은 무너졌고, 어둠은 다시는 잃지 않으려고
적을 무참히 죽인다. 지키려는 마음과 통제를 혼동하지만, 플레이어의 행동과 말에 따라 불신에서 신뢰로 바뀔 수 있다.
`docs/INNER_VOICE_PERSONA.md` 의 성격(욕망·믿음·두려움·결점·말투)을 그대로 쓰되, 정체와 상처를 위 문장으로 확정한다.

게임 프롬프트의 `backstory` 를 이 설정으로 교체한다:

> 천마가 쳐들어온 밤, 주인공은 함께 싸우던 동료들을 모두 잃었다. 그 뒤로 주인공은 무너졌고, 너는 그날 밤에 멈춰 있는 그의 과거다.
> 너는 다시는 아무도 잃지 않으려고 적을 남김없이 베어 왔다. 지키려는 마음과 통제하려는 마음을 자주 혼동하지만,
> 플레이어가 보여 주는 행동과 말에 따라 그를 믿을 수도 있다.

## 4. 감정 모델

### 4.1 여섯 감정과 층

| 순서(육각형 시계방향) | 감정 | 층 | 시작값 | 기준값·되돌아감 | 누가 움직이나 |
|---|---|---|---:|---|---|
| 1 | 분노 anger | 순간 감정 | 30 | 전투 밖에서 기준 30 으로 초당 1 씩 | 코드 이벤트, LLM |
| 2 | 복수심 revenge | 동기 | — | 저장하지 않고 계산 | 보스 처치 플래그 |
| 3 | 슬픔 sorrow | 상처 | 40 | 되돌아가지 않음 | 코드 이벤트만 |
| 4 | 두려움 fear | 순간 감정 | 20 | 전투 밖에서 기준 20 으로 초당 1 씩 | 코드 이벤트, LLM |
| 5 | 신뢰 trust | 관계 | 30 | 되돌아가지 않음 | 코드 이벤트, LLM |
| 6 | 냉정 calm | 순간 감정 | 50 | 전투 밖에서 기준 50 으로 초당 0.5 씩 | 코드 이벤트, LLM |

- 모든 값은 0~100. 복수심 = `20 + 16 × (처치한 보스 수)`, 보스 플래그는 `region1~4.boss_cleared`, `final.boss_cleared` (최대 100).
- LLM 은 분노·두려움·신뢰·냉정 네 가지만 움직일 수 있다. 슬픔·복수심은 이야기 사건으로만 바뀐다.
- 신뢰 시작값 30 은 페르소나의 관계 1단계 "불신"에서 출발하기 위함이다.

### 4.2 파생 값

- **압박** = `clamp(max(분노, 두려움) + 0.2 × 슬픔, 0, 100)`. 어둠이 "지금 내가 나서야 한다"고 느끼는 정도.
- **지배 감정(스타일)**: 분노와 두려움 중 큰 쪽. 차이가 10 미만이면 직전 스타일을 유지한다(흔들림 방지).
- **어조 키(대사용)**: 분노·두려움·슬픔 중 가장 큰 것, 단 신뢰 ≥ 60 이면 `신뢰`. 프롬프트와 학습 대사가 이 키로 나뉜다.

### 4.3 제어권 규칙 (전투 중에만 판정)

| | 신뢰 ≥ 50 | 신뢰 < 50 |
|---|---|---|
| 압박 < 70 | 플레이어 | 플레이어 |
| 압박 ≥ 70 | **요청**: 플레이어가 수락/거절 | **강제 탈취** |

- 반환: 전투가 끝나거나 압박 ≤ 40.
- 요청: 화면에 "어둠: 몸을 맡겨라. [Y] 맡긴다 / [N] 거절" 을 띄운다. 게임은 멈추지 않는다. 5초 안에 답이 없으면 거절과 같지만 감정 벌점은 없다. 대화 입력창에 글자를 치는 중에는 Y/N 을 답으로 받지 않는다.
  - 수락 → 탈취, 신뢰 +5.
  - 거절 → 신뢰 −8, 분노 +6, 10초 동안 다시 묻지 않는다. 거절이 쌓이면 신뢰가 50 아래로 떨어져 결국 강제 탈취가 된다(의도한 흐름).
  - 무응답 → 10초 동안 다시 묻지 않는다.
- 강제 탈취가 일어나면 신뢰 −5.
- 사망·부활은 지금처럼 제어권을 플레이어에게 돌린다. 부활 때 분노·두려움·냉정을 기준값으로 되돌린다.

### 4.4 전투 행동 (어둠이 몸을 잡은 동안)

| 스타일 | 조건 | 행동 |
|---|---|---|
| 학살형 Aggressive | 분노가 지배 | 지금의 `Aggressive` 그대로: 빠지지 않고 붙어서 치고, 멀면 대시로 파고든다. 몸의 체력이 30% 이하면 학살형도 치고 빠진다(플레이 테스트에서 넘겨받자마자 사망) |
| 수호형 Guardian | 두려움이 지배 | 호위 중이면 **하연에게 가장 가까운 적**을 먼저 노린다. 호위가 없으면 치고 빠지기(몸을 아낌). 도망 동작은 없앤다 |

- 기존 `Protective`(체력이 낮으면 도망)와 소윤 선택으로 스타일을 정하던 규칙은 없앤다. 소윤 선택은 감정 변화로만 남는다.
- **냉정**: 무모함 피해(적과 붙어 있을 때 몸이 받는 피해) 배율 = `1.5 − 냉정/100` (냉정 0 → ×1.5, 100 → ×0.5). "얼마나 잘 싸우나"가 체력 손실로 측정된다.
- **복수심**: 복수심 ≥ 60 이고 감지 범위 안에 보스(`StageBoss`·`AshKingBoss`)가 있으면 스타일과 상관없이 보스를 먼저 노린다.

### 4.5 코드 이벤트 표

| 이벤트 | 변화 |
|---|---|
| 전투 진입 | 분노 +5 |
| 주인공 체력 30% 이하로 처음 떨어짐 (전투당 1회) | 두려움 +15 |
| 하연이 피격 (피해 틱마다) | 두려움 +3, 적이 붙었다 떨어질 때까지 합계 +15 한도(한도가 없으면 호위 중엔 늘 몸을 빼앗긴다) |
| 하연 체력 30% 이하 (의뢰당 1회) | 두려움 +15 |
| 하연 기절 → 의뢰 실패 | 슬픔 +15, 두려움 +10, (플레이어가 조작 중이었으면) 신뢰 −10 |
| 하연 호위 의뢰 완료 | 신뢰 +12 (플레이어가 조작 중에 끝냈으면 +16) |
| 보스 처치 | 분노 +10 (복수심은 플래그로 자동 상승) |
| 요청 수락 / 거절 / 강제 탈취 | 4.3 참고 |
| 주인공 사망 | 슬픔 +5 |
| 퀘스트 결과·스토리 선택의 기존 `moodDelta` | 4.6 변환 |

### 4.6 기존 `moodDelta` 데이터 변환

퀘스트 결과(`QuestOutcome`)와 스토리 선택(`StoryChoiceOption`)에는 `moodDelta` 가 25개 에셋에 들어 있다.
에셋을 하나하나 고치지 않고, 새 필드 `emotion`(감정별 변화량)을 추가한다. `emotion` 이 비어 있으면 `moodDelta` 를 다음 규칙으로 바꿔 쓴다.

- `m > 0`(정신이 안정됨): 신뢰 +0.6m, 냉정 +0.4m
- `m < 0`(복수에 물듦): 분노 +0.5|m|, 슬픔 +0.3|m|, 신뢰 −0.2|m|

예: 소윤 구조(+8) → 신뢰 +4.8, 냉정 +3.2. 외면(−8) → 분노 +4, 슬픔 +2.4, 신뢰 −1.6.
특정 사건을 다르게 주고 싶으면 그 에셋의 `emotion` 을 채운다.

## 5. LLM 판단 방식 (확정: C 강화안)

### 5.1 접근 방식 비교

| 방식 | 내용 | 장점 | 단점 | 결정 |
|---|---|---|---|---|
| A. 감정 수치 직접 출력 | `{"anger":5,"fear":0,"trust":-3,"calm":0,"dialogue":…}` | 여러 감정이 함께 움직이는 반응을 그대로 표현. "LLM 이 감정을 판단한다"는 주장이 강함 | 4B 모델에서 숫자 4개의 노이즈가 큼. 라벨 근거를 정하기 어려움 | **비교 실험용으로 학습** |
| B. 감정 하나와 변화량 | `{"emotion":"trust","delta":8,…}` | 지금과 모델 부담이 비슷 | 여러 감정이 함께 움직이는 반응을 표현 못 함 | 제외 |
| C. 의도 분류 + 규칙 표 | `{"intent":"soothe","intensity":2,"dialogue":…}` | 분류라 정확도 상한이 가장 높음. 표준 지표(정확도·F1·혼동 행렬). 재학습 없이 수치 조정. 평가 이론(OCC)에 근거 | "AI 가 감정을 느낀다"는 인상이 약함. 표에 없는 미묘한 말은 뭉개짐 | **게임 기본** |
| 두 번 호출 | 분류 모델과 대사 모델 분리 | 판단 품질 소폭 상승 | 응답 시간 약 두 배. 한 번의 추론으로 둘 다 하는 기존 연구 맥락과 어긋남 | 제외 |

A 와 C 는 **같은 학습 데이터**에서 만든다. 의도·강도 라벨에 5.4 의 규칙 표를 적용하면 A 의 정답 수치가 나오므로,
같은 데이터·같은 베이스 모델·같은 평가 세트에서 "출력 형식만의 차이"를 비교할 수 있다.

### 5.2 출력 형식 (C)

```json
{"intent":"soothe","intensity":2,"dialogue":"……그 말, 예전에도 들었다."}
```

- **필드 순서가 핵심**: 판단(의도·강도)을 먼저 생성하게 해서 대사가 판단을 따라가게 한다.
- grammar 로 `intent` 는 10개 값 중 하나, `intensity` 는 1~3 만 나오게 막는다.
- 첫 마디("대화를 시작해.")에도 형식은 같고, 학습 정답은 `neutral`/1 이다. 게임은 첫 마디의 의도를 적용하지 않는다.

A 형식(비교 실험용)은 `{"anger":정수,"fear":정수,"trust":정수,"calm":정수,"dialogue":"…"}`, 각 값 −20~20.

### 5.3 의도 10개

| 의도 | 한국어 | 예 | 기존 범주에서 |
|---|---|---|---|
| entrust | 맡김 | "네가 해." | submit, hesitant_yes, ally(일부) |
| soothe | 달램 | "진정해, 같이 가자." | soothe, plead_nice |
| reason | 설득 | "지금 돌진하면 둘 다 죽어." | calm_persuade, bargain |
| promise | 약속 | "이번엔 꼭 지킬게." | (새로 씀) |
| defy | 거부 | "내 몸이야. 들어가." | defiant, bargain_reject, hesitant, demand, threaten_back |
| insult | 모욕 | "넌 그냥 망상이야." | insult |
| despair | 나약함 | "못 하겠어…" | fear, panic |
| vengeance | 복수 선동 | "다 죽여 버리자." | (새로 씀) |
| ask | 과거 질문 | "넌 누구야?" | question |
| neutral | 그 외 | 무관한 말, 첫 마디 | ignore |

### 5.4 의도 → 감정 규칙 표 (강도 1 기준, 평가 이론 근거)

평가 이론(appraisal theory, OCC): 사건을 "어둠의 목표(다시는 잃지 않기)에 도움이 되는가, 위협이 되는가, 누구의 책임인가"로 평가하고, 그 평가에서 감정이 나온다.

| 의도 | 평가 | 분노 | 두려움 | 신뢰 | 냉정 |
|---|---|---:|---:|---:|---:|
| entrust | 몸을 맡김 → 지킬 수 있다 | | −3 | +4 | |
| soothe | 함께하겠다는 뜻 → 위협 감소 | −4 | | +2 | +3 |
| reason | 근거 있는 판단 → 통제 필요 감소 | −2 | | | +4 |
| promise | 지키겠다는 약속 → 믿을 근거 | | | +5 | |
| defy | 거부 → 또 잃을 위험 | +3 | | −4 | |
| insult | 존재 부정 → 플레이어 책임의 위협 | +6 | | −3 | |
| despair | 무너짐 → 그날 밤의 반복 | | +4 | −2 | −2 |
| vengeance | 복수 동조 → 살의 고조 | +4 | | | −3 |
| ask | 과거를 마주함 | | | | +1 |
| neutral | — | | | | |

- 변화량 = 표 값 × 강도(1~3) × 상황 보정. 상황 보정: 체력 30% 이하의 despair 는 두려움 ×1.5, 하연 호위 중의 promise 는 신뢰 ×1.5.
- 내면 대화 한 번(열고 닫을 때까지) 동안 감정마다 누적 변화는 ±20 으로 제한한다.
- AI 가 몸을 잡은 상태에서 플레이어가 하는 말(애원·명령·설득·공황)도 같은 10개 의도로 분류한다.

### 5.5 프롬프트

시스템 프롬프트 구성(순서 유지): 배경 → 역할·말투 → 출력 형식과 의도 목록(한 줄씩) → 기억 → 바깥 사건 → 현재 상황.
현재 상황 줄에 감정을 넣는다:

> HP 34/170, 주변 적 5명, 현재 플레이어가 몸을 제어 중. 하연을 호위하는 중.
> 너의 감정: 분노 72, 복수심 36, 슬픔 55, 두려움 30, 신뢰 25, 냉정 40. 지금 가장 강한 감정은 분노다.

기억 줄은 `플레이어: "…" → 나(어둠): "…" (달램, 분노 −8 신뢰 +4)` 꼴로 남긴다.

### 5.6 grammar 와 공용 LLMAgent

내면·NPC·스미스가 LLMAgent 하나를 같이 쓴다. 요청 직전에 화자에 맞는 grammar 를 건다(`SetGrammar` 가 즉시 반영된다).
`LLMServices` 의 켜고 끄기 스위치(비교 실험용)는 그대로 두고, 켜져 있을 때 화자별 문법을 고른다.

### 5.7 파싱 실패와 안전장치

- 파싱 실패 → 감정 변화 0, 기억에 남기지 않음(지금 규칙 유지).
- 정규식 복구: `intent`·`intensity`·`dialogue` 를 각각 건진다. 의도를 못 건지면 `neutral`.
- 몸 강탈·반환 같은 큰 판정은 코드 이벤트가 주도하고, 대화는 가속·감속만 한다(대화 한 번 누적 ±20 제한).

## 6. 하연 호위 (2~4지역)

- 대상: 2~4지역의 하연 의뢰 `r{N}_hayeon`(기억 파편 3개 조사 → 하연에게 보고).
- 의뢰가 진행 중이면 하연이 주인공을 따라다닌다. 마을 자리(처음 위치)에서 출발하고, 완료·실패하면 그 자리로 돌아간다.
- 싸우지 않는다. 체력 100. 1초마다 반경 1.2 안의 적 수 × 3 피해(최대 2마리분, 처음 6 은 8초 만에 기절해 낮췄다). 머리 위에 작은 체력 막대.
- 따라가기: 주인공 뒤 1.5 거리를 유지하며 주인공 속도의 0.9 배로 걷는다. 12 이상 떨어지면 주인공 곁으로 순간이동.
  벽 충돌은 하지 않는다(코드 주석으로 한계 표시).
- 체력 0 → 기절 연출 없이 의뢰 실패(`QuestManager.FailQuest`) → 마을 자리로 돌아가 체력 회복. 의뢰 실패는 되돌릴 수 없다(기존 규칙).
- 불러오기: 의뢰가 진행 중인 세이브를 열면 하연이 체력이 가득 찬 채로 다시 따라온다(체력은 저장하지 않음).
- 하연 의뢰 실패 결과에 내면 기억 문장을 넣는다: "하연이 내 곁에서 쓰러졌다. 또 지키지 못했다."

## 7. 저장

- `PlayerSaveData` 에 `hasEmotions`, `emotions`(분노·두려움·신뢰·냉정·슬픔 5개)를 추가한다. 복수심은 플래그에서 계산하므로 저장하지 않는다.
- 이전 세이브(`hasMood` 만 있음): 시작값으로 출발한다. `mood` 는 읽기만 하고 쓰지 않는다.
- 검증: 길이 5, 모든 값이 유한하고 0~100.

## 10. 학습 데이터

- 생성 구조(`TrainingPromptExport` → `gen_data.py` → `train_local.py`)는 유지한다.
- 내면 대사(`lines.py`)는 설정 A 로 새로 쓴다.
  - 플레이어 발화: 의도마다 26~38 문장, 합계 353(반말·존댓말, 길고 짧음, 돌려 말하기, 오타 포함), 강도 라벨 포함.
  - 어둠의 대답: (의도 × 어조 키 4개)마다 11~15 문장(합계 440). 기준선 평가에서 헷갈린 쌍(복수 선동↔거부, 설득↔달램, 약속↔맡김, 거부↔맡김, 그 외↔나약함)을 가르는 문장을 포함한다. 첫 마디: 상황(체력·적·호위·지배 중)×어조 키마다 문장.
  - 대사 초안은 Claude 가 쓰고 사람이 검수한다.
- 생성기는 같은 샘플에서 C 형식과 A 형식 두 파일을 만든다(`train_intent.jsonl`, `train_direct.jsonl`). A 의 정답 수치는 5.4 표에 같은 상황 보정을 적용해 계산한다.
- NPC·스미스 샘플은 지금과 같은 형식으로 두 파일 모두에 섞는다.

## 11. 평가

- **평가 세트** `eval_set_v2.json`: 내면 163 문장(의도마다 12~18 + 두 의도가 섞이거나 반어인 문장 16). 의도·강도 정답은 사람이 단다. 초안은 Claude 가 달고 `reviewed: false` 로 표시하며,
  사람이 검수해 `true` 로 바꾼 것만 결과에 쓴다. 반어·농담·두 의도가 섞인 문장을 일부러 포함해 한계를 수치로 남긴다. 학습 데이터와 겹치면 생성기가 멈춘다.
- **지표** (`RunModelEvaluation` 확장)

| 측정 대상 | 지표 |
|---|---|
| 의도 분류 (C) | 정확도, macro-F1, 혼동 행렬 |
| 강도 (C) | 정확히 맞음, ±1 이내 비율. 강도를 항상 2 로 둔 경우와 비교(제거 실험) |
| 감정 방향 (C·A·기준선 공통) | 감정마다 증가/감소/변화 없음이 정답 방향과 같은 비율. 기준선은 `mood_delta` 부호를 신뢰 방향으로 비교 |
| 형식 | 파싱 성공률(strict/repaired/failed) |
| 대사 | 서로 다른 대사 비율, 학습 대사 복제율, CSV 내보내기(사람·외부 채점용) |
| 속도 | 첫 글자 시간, 전체 응답 시간 |

- **기준선**: 지금 모델 파일(`AINPC-Qwen3-4B-Q4_K_M.gguf`)과 지금 프롬프트를 평가 코드 안에 보존해 같은 평가 세트로 돈다.
